# 2026-10-28 标定页：本机对着棋盘格算内参

一句话：入口页多一个「标定」，对着棋盘格移 30 秒，App 自己算出 fx/fy/cx/cy/k1
并写进 `calib/profile.json` 的一行。不需要 adb、不需要 python、不需要 PC。

## 动机

部署到别人的手机上，标定不能靠 PC。而 `CalibStore` 已经支持多行、插值、增删 ——
缺的只是"这一行的数字从哪来"。这次补上。

## 改动

**计算（`app/src/main/cpp/calib.{h,cpp}`，编进 `liborb_slam3`）**

- `findChessboardCornersSB` + `CALIB_CB_EXHAUSTIVE | CALIB_CB_ACCURACY` 检角点。
- 视角去重：和已有视角的质心距离 < 6% 宽、包围盒尺寸差 < 12% 就丢掉。
- 九宫格覆盖：每个角点按位置落格，累计占比。
- 拟合 `calibrateCamera`，`CALIB_FIX_K2 | CALIB_FIX_K3 | CALIB_ZERO_TANGENT_DIST`，
  只估 `fx fy cx cy k1`。视角上限 40，不足 12 不拟合。
- 拟合后按单视角重投影误差剔除坏视角（超过中位数 2 倍且 ≥0.8 px），再拟合一次。

**接口**：`SlamBridge` 加 6 个外部函数（start / addFrame / views / coverage / finish / reset），
`jni_bridge.cpp` 只做翻译。

**页面（`CalibActivity` + `PatternView` + `activity_calib.xml`）**

```
打开相机 → 对准板子 → 点「锁定对焦」（显示 1.39 D）
        → 点「开始采集」→ 实时显示 视角 n/30 + 九宫格覆盖
        → 攒够自动拟合 → 否决检查 → 保存成一行
```

- **相机只跑连续对焦，不自动锁**（`CameraCapture.startContinuousFocus`）。
  锁由人点，锁错了有「重新对焦」放开。
- 采集时每 5 帧检一次，跑在独立线程；拷贝一帧 300 KB，约 6 次/秒。
- 「标定板」按钮把全屏棋盘格叠在预览上；「分享 / 打印」导出 PNG 走 FileProvider ——
  发给另一台设备、或者拿去打印店打一张 A4。
- 入口页「录制模式」旁边加了「标定」，两个都是"不选地图"的独立入口。
- 底部改成「一排次要按钮 + 一个全宽主按钮」（原文排三个，见决策 ⑨）。

## 决策

**① 用普通棋盘格，不用 ChArUco。**
Android 那边的 OpenCV 是 **4.6.0**，aruco 还在 contrib 里（4.7 才进 objdetect），
现有的 `charuco_9x6.png` 在手机上根本检不出来。而 `findChessboardCornersSB` 就在
`calib3d` 里，SB 版对模糊和光照比经典版宽容得多。代价是板子必须整块入镜。

**② 只估五个参数。**
k2/k3/切向在 640×480 的观测范围内辨识不出来（PC 那套实测里 k2 连符号都会翻）。
钉住它们让 fx 稳，也把需要的视角数从 150 降到 30。

**③ 视角只存内存，不落盘。**
30 帧 640×480 灰度约 9 MB。落盘再读回来只会让失败重来的代价更大。

**④ 否决规则写在代码里，而不是打印出来给人看。**
App 里没人替你看输出，算歪了只能拦住：RMS > 1.0 px、九宫格任一格 < 5%、视角 < 20，
任一条命中就"这次不行"，可以重来；过了才弹保存。

**⑤ 板子规格 6×4 内角点（7×5 个方格）。**
A4 横向正好接近 7:5，每格约 30 mm。640×480、`fx≈439` 下每格像素 = `439 × 0.030 / 距离`：
0.35 m 时 38 px、0.5 m 时 26 px、0.8 m 时 16 px。能直接标的档位落在 **1.25–3 D**。

**⑥ 不额外开一路相机输出。**
`activity_capture.xml` 里已经写明：多一路 surface 会让相机重新协商 stream，
可能换 sensor mode 或裁切，fx 跟着变 —— 那标定就白标了。所以标定走的就是
SLAM 用的同一个 640×480 流，也不做"1280 再缩放"。

**⑦ 复用 `CameraCapture`，不新写一套相机代码。**
它已经处理了 epoch、错误回调、YUV 转灰度；标定只是在 `onFrame` 里多挂一个消费者。

**⑧ 标定页用连续对焦，不复用 `beginSettle()`。**
第一版直接调了 `beginSettle()`，它的语义是"AF 收敛后自动锁死"—— 主界面需要这个，
但标定页需要的是"一直对焦，人说清楚了才锁"。在标定页的后果是：打开相机一两秒后
镜组就锁在**第一眼看到的东西**上（墙、桌面），再把板子拿过来，画面是糊的，
看起来就像"没有自动对焦"。
没有给 `beginSettle` 加一个 `autoLock: Boolean` 参数，而是新开 `startContinuousFocus()`：
一个是"准备好"，一个是"只是对焦"，两个相反的语义塞进同一个方法，调用点会看不出区别。

**⑨ 底部按钮改成一排次要 + 一个主按钮。**
三个 Material 按钮并排时，左右各 24dp 的内边距把可用文字宽度压到 ~49dp，
4 个汉字（14sp）要 56dp，于是「打开相机」折成两行、整排按钮跟着变高。
即使调小字号，三个同权重按钮并排仍然挤，所以按视觉层级拆开：
关闭 / 重新对焦 / 标定板 是 `TextButton`（矮、无底色），
锁定对焦 / 开始采集 / 停止并拟合 是全宽主按钮。

**⑩ 九宫格按屏幕方位摆，不按图像坐标摆。**
native 的下标是 `gy*3+gx`：`gx` 是图像 x，预览旋转 90° 后对应**屏幕上下**；
`gy` 是图像 y，对应**屏幕左右**而且左右镜像。第一版直接照这个下标打印，九宫格和屏幕差 90°。
真机第一轮的分布（中间列 20/40/20，其余六格 4–5%）就是两轴被交换留下的特征：
用户按"列 = 左右"的直觉上下推板子，实际填的是另一个轴。
`CalibActivity.displayCoverage()` 里转置 + 翻列，否决提示也从"第 N 格"改成方位词。

**⑪ 拟合后剔除偏离过大的视角，再拟合一次。**
RMS 是唯一的自动否决线，但它分不清"整套拍得不行"和"混进了几个坏视角"。
一两个拍糊、或者纸没压平、或者采集时手抖的视角，足以把 k1 拉偏、把整体 RMS 抬起来，
结果是一整套还能用的数据被判死。
现在先全体拟合，算出每个视角的平均重投影误差，超过中位数 2 倍（且不低于 0.8 px）的剔除，
再拟合一次；剔掉的个数返回给界面显示。剔完不足 12 个视角就不剔，保留第一版结果。

**⑫ 覆盖不够时直接给出下一个动作。**
九宫格的百分比看不出该干什么。现在每次刷新挑**最缺的那一格**，配一条动作提示。
板子通常钉在屏幕或墙上不动，所以要挪的是**手机**，而且方向相反 ——
要让板子落到画面左上角，手机得往右下挪。一次只提示一处，改完再看下一处。

**⑬ 判据从"九格每格 ≥5%"换成"画面外圈占比 ≥10%"。**
九格占比被画面长宽比放大：缓冲区 640×480，预览旋转 90° 后在屏幕上是 480 宽 × 640 高，
横向一格只有 160 px，而板子 6 个内角点横跨约 158 px —— 居中时正好占满一格，
24 个点全落中间列；再加上居中视角把中间格投满，两侧只能靠刻意贴边的少数视角喂。
真机上表现为"怎么拍都提示不通过"，这和操作无关，是判据在惩罚几何。
换成外圈判据：归一化坐标 `max(|u|,|v|) ≥ 0.7` 的角点占比 ≥ 10%。它跟长宽比无关，
板子在中间时是 0，推到边上才涨 —— 这才是约束畸变真正需要的东西。
九宫格保留显示，只作方位参考，不再当门槛。

## 验证

**未重编、未真机。** ⑧–⑬ 都是这一轮真机反馈改的，同样还没有重编验证。

| # | 做什么 | 期望 |
|---|---|---|
| ① | 入口页 → 标定 → 打开相机 | 预览出现；相机能力日志里 `支持640x480: true` |
| ② | 对准板子 → 锁定对焦 | 状态栏显示 `● 对焦已锁定 1.39 D（约 0.72 m）` |
| ③ | 开始采集，板子平移 + 俯仰 30 秒 | 视角数往上涨；九宫格逐格变亮 |
| ④ | 攒够 30 个视角 | 自动拟合，弹窗显示 fx/fy/cx/cy/k1 和 RMS |
| ⑤ | 保存 | `files/calib/profile.json` 出现一行；回到主界面新建地图时日志变成 `内参（档位插值）` |
| ⑥ | 故意只露半块板 | 一直收不到视角；或用 15 个视角强行停止 → 提示视角不够 |
| ⑦ | 板子只在中间晃 | 拟合被拒：外圈占比接近 0% |
| ⑧ | 同一档复标 | 覆盖那一行，不新增 |
| ⑨ | 分享 / 打印 | 相册/微信里收到一张黑白棋盘 PNG，四边有白边 |
| ⑩ | 打开相机后把板子从远移近 | 状态行的「实时对焦 x.xx D」跟着变 —— 说明连续对焦在跑 |
| ⑪ | 故意在墙上锁一次，再点「重新对焦」 | 数字重新跳动；「重新对焦」按钮消失，主按钮变回「锁定对焦」 |
| ⑫ | 窄屏（360dp） | 底部每个按钮单行，不折行 |
| ⑬ | 把板子推到屏幕左上角 | 状态行左上格明显上涨，右下列不动 —— 方位和屏幕对得上 |
| ⑭ | 采集时故意快速挥一下板子 | 保存弹窗出现「剔除了 N 个偏离的视角」，RMS 比剔除前小 |
| ⑮ | 采集时只看状态行不数格子 | 「下一步：手机往右下挪…」照着做，对应格子就涨 |

板子得用 **A4 打印**或 ≥20 cm 的屏（平板/电视）。**手机屏幕不够大**：7 cm 宽在
0.4 m 处每格只有 ~10 px，SB 检测器大概率检不出来。

## 遗留

- **没走 1280 流**（理由见决策 ⑥）。如果 A4 在 0.7 m 以上还是检得吃力，
  再考虑"标定单独开一路更高分辨率、算完缩放"，但那时必须实测两个分辨率的
  裁切是否一致。
- **近距档**（3 D 以上）需要把板子拿到 0.25–0.35 m，A4 会占满画面、覆盖不好；
  要用更小的板。
- **板子没真打出来之前，检出率只是估算**。第一次跑先确认"4000 万像素的手机
  对着 A4 在 0.5 m 能不能稳定出 30 个视角"。
- **一档 = 一个对焦屈光度**：想要 1 D 和 2.5 D 两档，就对着两个距离各标一次。
- **没测 IMU 频率**：profile 里那个字段仍然没人写，主界面按 402 Hz 兜底。
- **出厂内参只在 `CalibStore.factory` 里**，标定页没有暴露这个入口（实测它是名义值，
  不值得做按钮）。
