# 2026-11-04 点–面约束先按锚点深度选层，再拟合；拟合方程改用相对坐标 + double

## 动机

2026-10-30 那版把点–面约束接进测距（`fitPlaneAt` + `correctDepth` + `refinePinned`），
但三轮真机里它**从未真正生效**：`[M6] 面` 155/156 次是 `内点0 残差0.0% 入射0.00`。
当时的归因是「96 px 窗口里有多个表面，全量最小二乘拟出妥协平面，随后内点剔除把点全判成外点」。

**2026-11-04 加了选层之后，真机日志推翻了这个归因。**

```
[M6] 面[十字] 窗35/层30 内点0 残差0.0% 入射0.00 深度1.74→1.74 拟合失败
[M6] 面[钉点] 窗44/层43 内点11 残差2.5% 入射0.00 深度1.66→1.66 拟合失败
```

459 次拟合里 **455 次 `内点0`**，而层内点数有 30~50 个；唯一一次「通过」是
`窗44/层35 内点29 残差2.9% 入射0.61 深度2.40→2.27`。选层确实在起作用（窗→层会掉 5~15 个点），
但**内点还是 0** —— 问题不在「有几张面」，在拟合方程本身。

根因是数值条件：`fit()` 用 `Matrix3f` 且直接拿**绝对像素**建正规方程。
`r = (u, v, 1)` 里 u≈320、v≈240，法矩阵特征值比约 **2.6×10⁷**（λ₁≈2.3e5·N，λ₃≈0.009·N）。
Eigen 的秩判据是 `3·ε·maxpivot`，float 下等于 `3×1.19e-7×2.3e5·N ≈ 0.083·N`，
**比 λ₃ 大 9 倍** ⟹ 秩判成 2，`FullPivLU::isInvertible()` 直接 false，
函数在第一次最小二乘就返回。`内点` 自然恒为 0、`残差` 恒为 0.0%、`入射` 恒为 0.00 —— 与日志逐字对上。

这也解释了为什么偶尔能过一次：点铺得够开（σ 大）时 λ₃ 抬高，勉强越过阈值。

## 改动

- `app/src/main/cpp/measure_center.cpp`
  - `fitPlaneAt` 的 `uvz` 改成存**相对目标像素**的 `(du, dv, 1/Z)`，正规方程用 `Matrix3d` / `Vector3d`。
    平移后条件数降到 1e3 量级，double 再留一倍余量。目标像素处 `du=dv=0`，`invZ` 直接是常数项。
  - 平面法向的还原同步改：`1 = a·fx·X + b·fy·Y + [a·(cx−u) + b·(cy−v) + c]·Z`。
  - `fitPlaneAt` 加 `refZ` 入参：`refZ > 0` 时只保留 `|z − refZ| ≤ kSurfLayerFrac · refZ` 的点再拟合。
    选层排在算出 z 之后 —— 它只跟深度有关，而深度要 `GetWorldPos()` 加锁，放在像素筛后能少拿一批锁。
  - `PlaneFit` 拆出 `window`（选层前）、`total`（选层后）、`solved`（第一次最小二乘是否出解）。
    `total` 是「内点过半」判据的分母，**另一层不再能把内点率拖到 50% 以下**。
  - `correctDepth` 传 `pc->z()` 选层；失败原因分三档（点太少 / 方程奇异 / 内点不足），
    四类结果各记一次统计。末尾按 `kSurfaceApply` 决定要不要写回 —— 现在是 `false`，只观测。
  - `planeDepthAt` 传 `0.f`：兜底没有锚点可参照，**本轮不动**，行为与改动前逐位等价。
  - `centerMeasure` ④：`correctDepth` 会就地乘上未平滑的 k，改用草稿变量 `pcFit` 接，值本身丢弃；
    修正比走 EMA（`kSurfRatioAlpha = 0.3`）后同时作用于 `distance` 和 `wx/wy/wz`。
  - 换锚点、② 跳变解锁、⑤ 平面兜底三处把 `ratioEma` 归 1。
  - `logSurface` 的 1 Hz 限流按 tag 拆开（原来两个 tag 共用一个 `static`，调用多的那个把另一个饿死），
    格式加 `窗%d/层%d`。
  - 新增 `noteSurface`：每 5 秒一行 `[M6] 面统计[...] 尝试 通过 拟合失败 门控 差太多`。
    1 Hz 明细是抽样，算不出成功率，这一行才是验收依据。
- `app/src/main/cpp/measure_center.h`
  - `CenterMeasureState` 加 `ratioMp` / `ratioEma`；`SurfaceDepth.total` 注释改成「选层后参与拟合的点数」。
- `app/src/main/cpp/slam_engine.cpp`
  - `refinePinned` 加死区 `kRefineDeadband = 3%`：比值在 1±3% 内不动。依据是第二轮实测
    钉点修正比中位数 1.000（p10 0.979 / p90 1.014）—— 没有可修的系统偏差，只有噪声。

## 决策

- **采用：以锚点深度为中心 ±30% 选层。** 要修的就是锚点自己；以它为中心才能把修正量关在带内。
  否决「选点数最多的那一层」——画面里的近处遮挡物（手、桌沿）会把层抢走，修正量就失控了。
- **否决：RANSAC / 深度聚类。** 96 px 窗口里通常只有 5~20 个点，这个稀疏度上聚类不稳；
  而选层只需要把明显属于另一层的点去掉，不需要找最优模型。
- **否决：选层后不足 5 点就回退到全窗口。** 回退等于把「妥协平面」请回来。
- **纠正：根因不是多表面，是 float 的秩判据。** 选层是必要的（窗→层确实掉点），
  但它救不了一个根本没解出来的方程。这一条是加了 `窗/层/内点` 三个数并列之后才看见的 ——
  只有一个「内点 0」，会把「多表面」和「方程奇异」混成同一个现象。这也是本轮加 5 秒统计的原因。
- **采用：先关掉平面修正的落地，只保留观测（`kSurfaceApply = false`）。**
  三轮数据指向同一件事：修正比自身散布 ±2~8%，**和它要修的误差是同一个量级**；
  中位数 0.993 说明没有系统偏差可修。继续调阈值只是把噪声换个幅度。
  留一条编译期开关，等有「开/关 + 已知长度」对照再决定要不要开。
- **采用：修正比 EMA（α=0.3）。** 否决了「只在门控通过的帧应用修正、其余帧直接回原值」的写法：
  门控在真实场景里是间歇性通过的，那样读数会跟着门控一起闪，幅度就是当时的修正量。
  代价是门控不通过时也在用一个没有本帧证据的修正 —— 由「目标回 1」和「换锚点重置」两条兜住。
- **采用：`out.surface` 按「输出是否含修正」定义**（`|ratioEma−1| > 0.5%`），不再只表示「本帧门控通过」。
- **保留 `kSurfRelMax = 0.25`。** 选层之后它的角色从「主要挡板」退化成「外推异常兜底」。

## 验证

**第一轮（只有选层，未修数值）：已构建、真机 7 分钟，失败。**

```
$ adb logcat -v threadtime -s slam:V > /tmp/slam-1104.log
面[十字] 265 条 / 面[钉点] 194 条 / 面统计 105 条
内点0: 455   内点>0 但未过半: 3   过半: 1     ← 共 459 次拟合
[十字] 全部 通过0(0%) 拟合失败N 门控0 差太多0
```

按深度分档，`内点0` 在 <2 m 有 307 次、2~3 m 123 次、>3 m 25 次 —— **和距离无关**，
所以不是「远处点太吵」，是方程本身没解。

同一份日志里测距链本身是稳的：

```
[M6] 段长 1.153 - 0.390 - | 锚点 381 381 449 449 557 | 图尺度 1.5605 | 点 5
[M6] 段长 1.163 | 锚点 381 381 | 图尺度 1.5605 | 点 2      ← 两分钟后

真值 1.2 m / 0.4 m，读数 **1.153 / 0.390，两分钟内 ±0.5% 不摆**，`图尺度` 全程不变。
残余是 **−3%~−4% 的系统尺度误差**，与平面无关（属「fx 425 vs 模板 439」和「已知长度校准没做」）。
`地图被重置` 36 次全部落在 19:44~19:46 的 IMU 初始化段，19:47 之后测量期间没有重置。

通过率从 0.6% 上到 40~90%，`方程奇异` 归零 —— **数值修复生效了**。

但段长抖了：

```
n=72  均值1.182  标准差0.022(1.9%)  极差1.141~1.246(8.9%)

上一轮平面没生效时是 1.153、两分钟 ±0.5%。原因就在第二行：**钉点修正比中位数 1.000**。
钉点本来就是地图点，和邻域点同源，平面看不出它自己的偏差 —— 没有可修的系统偏差，
只有 ±1~2% 的拟合噪声。两个端点各抖 2%，段长就成了 4%。

死区挡掉了 86% 的调用，但**剩下 14% 的修正一次就能把端点推 4~8%**，段长照样一跳几厘米。

**第四轮（`kSurfaceApply = false`）：未构建 —— 只算不改。**

`correctDepth` 仍然完整地选层、拟合、过门控、打日志、记统计，只是在最后一步不写回坐标。
读数回到平面介入前的行为，观测数据一条不少。

准确性方面要说清楚：

- 本轮 1.182 / 0.395，真值 1.2 / 0.4，比上一轮的 1.153 / 0.390 更近；
- 但两轮不是同一张图（图尺度 2.05 vs 1.56），**不能把改善归因给平面**；
- 而且十字的修正是**负**的（p50 0.972，把读数改小），方向上与「读数本来就偏小」相反 ——
  改善更可能来自另一张图的尺度；
- 十字那条 −2.8% 的系统修正没有真值无法判定真伪，需要一次开/关对比（见遗留）。

第三轮的判读顺序（前一条不过就不看后面）：

1. `[M6] 段长` 极差应回到 1% 量级 —— 死区是否生效，只看这一条。
2. `[M6] 面统计[钉点]` 通过率仍应 ≥40%；掉太多说明死区把真修正也挡住了。
3. `面[十字]` 与 `面[钉点]` 各自 ≤1 s 一行（限流确实拆开了）。
4. 正对一面平墙：`层≈窗`、通过率接近 100%（没误伤本来就拟合得好的场景）。
5. 修正生效瞬间读数不再单帧跳变。
6. **墙角专项**：十字对准 90° 内角几秒 —— 期望 `内点/层 < 50%` → 拟合失败 → 读数不变。
   若「通过」且修正 > 5%，记下当时的 `窗/层/内点`，下一轮收紧带宽或加「整层残差」判据。

## 遗留

- **角落与曲面：选层按深度分，分不开「两面在同一深度段」的角。** 三种情况（fx≈425、1.3 m、96 px 粗算）：
  - 砖块 0.5 m + 背景墙 2 m → 只留砖块那层，正是要修的；
  - 两面墙 90° → 两层都留，折中面只覆盖一条窄带，内点约 24% < 50% → 拟合失败 → **不改原值**，安全；
  - 浅角 135°、圆柱面 → 内点占比高，门控能过，十字处偏差约 5%（6 cm）。

  第三行是「平面假设」的固有误差。现有门控（5% 内点带、4% 残差、cos≥0.3）都测不出「面是弯的」。
  要压住只能缩小窗口或按像素距离加权拟合。
- `kMinPlanePoints = 5` < `kSurfMinInliers = 6`：5 点的层能拟合但永远过不了门控。
- **十字那条 −2.8% 的系统修正真伪未验证（现在被 `kSurfaceApply=false` 关掉，不影响读数）。**
  方向上是把读数改小，而实测读数本来就偏小 3~4%，两者同向 —— 要么平面在纠一个真实的前后景误吸附，
  要么它把背景锚点拉到了前景面上。验证方法：拿 1.2 m 砖块固定位置，开/关各测一轮，比哪个更接近 1.2。
  在验证之前不要把它当精度提升，也不要重新打开。
- **钉点侧 34 次「点太少」而十字 0 次**：钉点在画面里的位置和纹理不如中心，
  96 px 窗口经常凑不够 5 个点。这不是 bug，但说明钉点的平面刷新本来就没多少机会触发。
- `kSurfRelMax` 现在几乎失效：「与锚点差太多」全程只有 1 次，1% 的门控 → 外推兜底，可以考虑放宽。
- 要收紧时 `kSurfLayerFrac` 和 `kSurfRelMax` **必须一起降到 0.20**，只降一个等于白选。
- 锚点自身深度偏 > 25% 的点，这条路径修不回来。这是能力边界。
- `measureState` 跨 `start()` / 地图重置不清（P2 未做），`ratioEma` 会跟着残留。
- 中心兜底仍未选层；`±` 不确定度、长链重锚、IMU 杆臂、已知长度校准仍未做。
- **−3%~−4% 的系统尺度误差**：比平面修正更直接地影响读数。下一步要么拿已知长度做一次标量校准，
  要么先查 fx 425 与模板 439 的差。
