# 2026-10-21 历史轨迹接到小地图

一句话：小地图上多一层**蓝色历史轨迹** —— 只画「当前轨迹所属那张图」在
`map-<id>/` 里的已归档轨迹；抽屉里有总开关，管理页能逐条隐藏（跨重启保留）或删除。
合并发生、还没存图的那段窗口里，文件夹按内存里的链乘 `T_on`，**合并后立刻能看见**。

## 动机

上一批（[2026-10-21-map-folders-for-trajectory.md](2026-10-21-map-folders-for-trajectory.md)）
把轨迹按 atlas 图分进了 `map-<id>/`，`TrajectoryStore.tracesFor()` 也写好了，但**没有
任何界面读它** —— 磁盘上攒着以前每一趟的轨迹，小地图上只看得到本趟那条白线。

需求原话：「把轨迹接到小地图上，并且可以管理当前对应地图的轨迹是否显示或删除」，
并特别要求「着重注意一下运行时合并的情况怎么显示轨迹」。

## 改动

**上游（补丁 29）**

- `Atlas`：
  - `GetBestMapId()` —— 图集里 id 最大且 `KeyFramesInMap() > 0` 的那张；
  - `GetDisplayTransforms(displayId, …)` —— 按合并链算出每个文件夹 id 到显示坐标系的
    累计变换（族算法，见下），每条 9 个 float，`displayId` 固定排第一；
  - `DropMergeRecords(n)` —— 丢掉链里最前面的 n 条。
  - 合并链的语义改成「**还没写到磁盘上的**合并」。
- `System`：`GetDisplayMapId()`（轨迹图的 id，没有轨迹时退回 `GetBestMapId()`）、
  `GetDisplayTransforms()`、`DropMergeRecords()`。
- `LoopClosing::MergeLocal2()`：`RecordMerge` 从 `ApplyScaledRotation` **之前**挪到**之后**。
  显示侧一看到链就会去变换文件夹，那时当前图必须已经搬完 —— 否则会出现几百毫秒的
  「历史轨迹已经在新系、实时轨迹还在旧系」。
- `slam_engine`：
  - `requestSaveMap()` 把当时的链长度存进请求；`maybeSaveMap()` 在**存图成功**之后
    `DropMergeRecords(该长度)` —— 修掉「下一次存图再乘一遍 `T_on`」；
  - `displayTransforms()`：取 id + 算变换一次做完；
  - `readTrajFile()`：读 8 列 TUM、只取位置做 `p' = s·R·p + t`、stride 抽稀到 buffer。
- `jni_bridge` / `SlamBridge`：`nativeDisplayTransforms` / `nativeReadTrajFile`。

**我们这侧**

- `MapView`：独立的历史轨迹层（蓝色 `0xCC64B5F6`、1.4dp），画在点云之后、
  白色实时轨迹之前；所有条共用一个 `Path`。
- `MainActivity`：
  - `refreshHistory()` —— 只在「会话路径 + displayId + 变换」变了 / 置脏时列目录、
    读文件；4 Hz 的 ticker 不反复碰磁盘；
  - 抽屉里 `swHistory`（默认开）+ `btnHistoryManage`；管理页逐条「显示 / 隐藏」「删除」；
  - 隐藏状态存 `SharedPreferences` 的 StringSet（绝对路径）；
  - 载入地图时**提前**把 `sessionDir` 定为 `.osa` 的父目录 —— 没启动 SLAM 也能管理；
  - `refreshMap()` 的 hint 改成「真的没东西可画」才出现 ⟹ 停止后白线定格 + 历史照常画；
    当前位置的琥珀点改成只在 `slamRunning` 时画（停止后 `poseValid` 是旧值）。
- `activity_main.xml`：历史轨迹开关 + 管理按钮。
- `docs/tutorial/APP_DESIGN.md` §9 一句。

## 决策

**① 显示哪张图的文件夹：`GetTrajectoryMapId()`，没有轨迹时才退回「id 最大且 KF>0」。**
小地图的位姿、点云、实时轨迹全是**当前图**的系；把别的图的轨迹叠上来必然错位。
不用 `runMapId`（那是 `stop()` 的快照，跑着的时候会滞后），也不用
`mpAtlas->GetCurrentMap()`（坏图窗口里它会抱着锁 `usleep`）。
刚载入 / Reset 之后没有轨迹，此时退回载进来的那张，才能让「准备完、还没启动」也看得到。

**② 合并发生之前不画旧图的历史。**
载入旧图后当前图是一张**新的空图**，跑出来的新轨迹和旧图各有一个原点。只有
`MergeLocal2` 把当前图搬到旧图的系里之后，两边的轨迹才可叠。所以「一启动就看不到
载入那张图的轨迹」是**对的**，不是漏了 —— 验证表里专门有一条盯着这个。

**③ 合并窗口里：被吸收目录原样，幸存图那一族再乘 `T_on`，多跳按链累积。**
每个文件夹 id 带一个「族主」。合并 `(S ← A, T_on)`：族主是 S 的全部乘 `T_on`，
然后把 A 那一族的族主改成 S、**变换不动**（A 本来就在最终系里）。这样
「合并 A 进来之后又合并 B」时，A 的文件也会被第二次 `T_on` 带上。
**只输出 display 那一族** —— 地图被重置、换过 current map 之后，链里可能还留着别的图
的合并且和 display 毫无关系。
这段数学放在 C++（`Atlas::GetDisplayTransforms`）：Kotlin 再写一遍四元数乘法
就是两份要同步的公式。

**④ 合并链的语义从「本进程发生过的合并」改成「还没落盘的合并」。**
上一批只在 `PostLoad()` / `ReloadAtlasFrom()` 清链，存图成功后**不清** —— 同一份
atlas 里第二次存图会把同一条 `T_on` 再乘一遍，磁盘和显示都会错。现在
`requestSaveMap()` 记下链长度、存图成功后 `DropMergeRecords` 掉那几条：
- 失败 / 不保存 ⟹ 一条不丢（`.osa` 没写成，磁盘不该动）；
- 存图期间 LoopClosing 补记的新链不会被误删（只丢前 N 条）；
- 之后 `GetMergeRecords()` 写进轨迹 json 的也正好是「这批文件要乘的变换」。

**⑤ 只在上下文变化时读盘。**
历史文件只在「存图归档、删除、换图、合并、开关」这些动作里变，全部由这一侧发起。
`refreshHistory` 用一个 `session 路径 + 所有变换` 的字符串做 key，没变就直接返回 ——
否则 ticker 每 250 ms 会把几 MB 的 txt 重读一遍。文件按 2000 点抽稀，主线程同步读
（一次换显示只发生一次，不值得为它引一套后台线程）。

**⑥ 停止后继续画。**
用户确认的口径。hint 从「`!slamRunning` 就盖住」改成「三样都没有才盖住」；
反过来，只在 `slamRunning` 时画当前位置 —— 停止 / 还原 atlas 之后 `poseValid`
是上一帧的旧值，画出来会和历史轨迹的坐标系对不上。

**⑦ 隐藏按绝对路径记，删除删 `.txt` + 同名 `.json`。**
用户确认：会话目录本身就是身份，路径天然唯一；删数据时把元信息一起删，免得留下
一堆没有轨迹的小文件。**不动 `.osa`**，也不动 atlas 里的关键帧。

**否决的方案：**

- **在 Kotlin 里做四元数合成 / 变换。** 公式在 C++ 已经有一份（`transformTrajFile`），
  两份迟早对不上。
- **每拍重读历史文件。** 4 Hz × 几 MB，纯浪费；文件只会被自己的动作改。
- **未合并就把载入图的历史叠上来。** 两张图各有一个原点，画上去是错的 —— 而且错得
  很像「SLAM 漂了」。
- **用一个「历史轨迹」的全局布尔，不记逐条隐藏。** 用户明确要逐条 + 跨重启保留。
- **把 `traj/` 里没归档的也画出来。** 它们不属于任何存下来的图，坐标系不一定一致；
  留给以后的一键清理。

## 遗留

- **只显示 / 管理「当前轨迹所属那张图」的轨迹。** 一个 atlas 里有多张独立图时，
  别的图的文件夹看不到；选图 UI 是以后的事。
- **进程若死在「存图成功」和「归档重组」之间**，文件夹会停在旧坐标系，而链已经丢了
  （链只在内存）。和上一批同样的窗口，只是这次多了一个「链已经清掉」的分支。
- **合并那一刻在主线程重读所有历史文件**（几 MB、几十毫秒）。合并本身已经在停
  LocalMapping，暂不优化。
- **已经变换过的 json 不改**：`map_id` / `merges` 记录的是那一趟写盘时的情况，
  变换只改 `.txt` 的坐标。管理页显示的「图 #id」用的是**文件夹 id**，不是 json 里的。
- **删掉本趟刚归档的那条**时，内存里的白色实时轨迹还在（下一次启动才消失）——
  磁盘历史和内存轨迹是两层。
- **`traj/` 里的松文件**仍然没有入口（不显示、不能删），留给以后的一键清理。
