# 2026-10-15 上机遗留①②：**放大档位往下补三档** + **重置时显式清轨迹**

一句话：昨天里程碑 B 首次上机暴露的三条里，先把**能修的两条**修了 ——
放大不够用（补档位）和重置后轨迹不清（那个「自动滤掉」只在换 `Map` 对象时才成立）。

## 动机

上机后用户给了三条，其中两条是明确的：

> 1 尺度设置不太合理，能放大的还不够，或许可以设置一个上下限，按动连续放大缩小之类的
> 2 地图重置后轨迹未清除

（第三条「感觉重置次数变多了、初始化难一些」**未多次验证**，没动。）

**②的根因在昨天那份记录里已经定位**：设计上靠「跨图过滤」自动滤掉老帧，而那建立在
**重置会换一张 `Map` 对象**上（`Tracking::Reset()` → `clearAtlas()` + `CreateNewMap()`）。
真机走的是 `Tracking::ResetActiveMap()` → `mpAtlas->clearMap()`：**原地清空同一张 Map**
⟹ 老帧的参考帧 `GetMap()` 还等于当前图 ⟹ 跨图判据根本看不见它 ✗

⚠️ 这行代码是 `2026-10-14-trajectory-follows-keyframes.md` 决策五**删掉**的。

## 决策

### 一、`ZOOM_DEFAULT` 改成**从表里找**，不写下标

表一改，写死的下标就悄悄指到别的档位上 —— **不会报错，只是默认比例变了** ✗。
`indexOf` 找不到会返回 `-1`，`ZOOM_M_PER_DP[-1]` 在构造 `MapView` 时就炸 ⟹ **响得早** ✓

⚠️ 代价：`FloatArray` **没有 `indexOf`**（那是 `List`/`Array<T>` 的）⟹ 表得写成 `listOf`。
13 个元素、每个被装箱一次，可以忽略 ✓（第一版写成 `floatArrayOf` 编译不过，已改）。

### 二、重置时清轨迹 —— 两条路都要盖住

- `Reset()`：换 `Map` 对象 ⟹ 跨图判据本来就能滤 ✓
- `ResetActiveMap()`：**原地清空同一张图** ⟹ 跨图判据看不见 ✗

**不分辨是哪条路，一律显式清** —— 判据是同一个（`r.kfCount == 0`），
而「一次运行 = 一份轨迹」本来就是我们要的语义 ✓（和 `start()` 里那次清是同一个意思）。

⚠️ 副作用：重置那一段进不了 `trajectory.txt` 了。**这正是想要的** ——
重置之后世界系整个换了，两段拼起来本来也没有意义。

⚠️ 加锁：这个调用在 worker 里、`orbTrack` **返回之后**，此时 `Track()` 早放掉了
`mMutexTraj` ⟹ 再拿一次不会自锁 ✓

### 三、"按住连发"用 **`onLongClick` 起头 + `onTouch` 收尾**，不自己写手势

`View` 那套（点击 / 长按）是现成的，自己判 `ACTION_DOWN` 再延时反而是重写一遍它 ✗，
而且**会和点击打架**（手一抖就同时收到「按住那档」和「点击那档」）。

所以：`onClick` 管一下 ✓、`onLongClick` **返回 true**（消费掉 ⟹ 长按之后不再补一次点击 ✓）
只负责**起**定时器 ✓、`onTouch` 只看 `ACTION_UP` / `ACTION_CANCEL` 负责**停** ✓
⚠️ `onTouch` 必须**返回 false**，否则事件被吃掉，点击和长按都不会发生 ✗

两个细节：

- 长按判定一成立就 **`post(r)` 立刻走一档**（不是等 95 ms）—— 否则按下去半秒没反应，
  看着像坏了 ✗
- 定时器挂在 `uiHandler` 上 ⟹ `onDestroy` 里那句 `removeCallbacksAndMessages(null)`
  **顺手就把它清了** ✓ 不用在 onStop/onPause 里再写一遍 ✓

### 四、上限砍到 5000 —— 代价是**大场景更早开始抽稀**

`kMapPointsMax` 决定两件事：① 快照里最多几个点；② 全图超过它就按 `ceil(n/5000)` 抽。

砍掉的**不是**「画不下」的问题（5000 个点画在 140dp 的小窗上早就糊了），
砍的是**每秒那一趟的分配和拷贝**：`mapSnap` 从 240 KB 降到 60 KB，
`Snapshot` 每拍拷的那份也一起降 ✓ 快照重建时逐点访问的**上限**从 20000 降到 5000 ✓

⚠️ 副作用：地图点超过 5000 之后，切片拿到的是**抽稀过的** 1/k，而且在 20000 那版里
「室内规模根本不会超、所以没差」那个判断**不再成立** —— 一个房间跑几分钟就可能过 5000 ✗
（这条本来就在「遗留」里挂着，现在它**提前**变成了现实。）

### 五、`cloudScratch` 改成**按需长**，不写死 2 × 20000

它本来就该跟着快照的**实际点数**走 —— 上限是 C++ 那边的事。写死一个数字的话，
今天这种「改上限」就要在三个文件里同步 ✗（而且漏掉一处**不会报错**，只是要么浪费内存、
要么数组越界）。

⚠️ 顺带删掉了写循环里那句 `if (cnt*2+2 > cloudScratch.size) break`：缓冲现在**按
`ptsN*2` 精确分配**，而 `cnt` 最多到 `ptsN` ⟹ 那句已经**恒不成立**，留着只会让人以为
「这里要防越界」（真正的保证在分配那一行）。
