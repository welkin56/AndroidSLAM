# 2026-10-12 折线的边：**背朝点时画出一条横跨屏幕的线** —— 改成近平面裁剪

一句话：**「把相机后面的点夹 z 到一个小正数」这个近似，只在点刚穿过相机平面时方向是对的。**
远一点就错，再远**反号**。改成把线段**沿自己**插值到相机平面前一点再投 —— 数学上等价于
图形学里的**近平面裁剪**。

## 动机

用户报的（真机）：

> 「**我背朝点的时候，突然出现了一条横跨屏幕的线**」

## 根因：那个近似是什么

[2026-10-11](2026-10-11-two-point-measurement.md) 为了让「一端在相机后面」的边还能画，
在 `projectWorld` 里做了这么一件事：

```cpp
const float zc = front ? z : kMinZ;   // 后面的点，z 夹成 0.05
o[0] = fx * x / zc + cx;
```

**它等于把那个点沿光轴平移到相机前面（x, y 不动），再投。** z 是常数时像素就只由
`(x, y)` 决定 —— **效果上就是「只按 xy 画」。**

### 为什么「只按 xy」对单点没事、对线段就错

**一个点在画面上的位置，本来就只由它的视线方向决定**（`x:y:z` 那个比例，**深度不影响**）。
所以单看点没问题。

**但线段的走向靠的正是深度差** —— 3D 直线投到画面上是**射向消失点**的线，
消失点 `∝ (Dx/Dz, Dy/Dz)`，`D = 两端之差`。**把 z 定死 ⟹ 深度差没了 ⟹ 方向就没了。**

三个数（fx=435, cx=320）：

| A（相机系）| B（相机系）| 真值 | 夹 z |
|---|---|---|---|
| (0.5,0,**1**) | (0.49,0,**−0.01**) 刚穿过 | 324 | 4583 ✓ 同侧 |
| (0.5,0,**1**) | (**0.5**,0,**−1**) | 537 | 4670 ✓（这条线段平行于光轴，运气好）|
| (0.5,0,**1**) | (**−0.5**,0,**−1**) | **537（右）** | **−4030（左）** ✗ **反了** |

**第三行就是「横跨屏幕」** —— 点在你背后偏左，线却甩向左边，从右到左穿过去。

## 改动

**核心：投影从「一个点」变成「一条线段」。**

```
一条线段 (A, B)：
   A.z > 0  →  A 的像素照常算
   A.z ≤ 0  →  **沿线段朝 B 插值**到 z = kNearZ，投那个点
   两端都在后面 → 这条不画
```

**这就是近平面裁剪**（GPU 管线里就在这一步做：先把图元按 `z = zNear` 裁掉，再投影）。

| 文件 | 改什么 |
|---|---|
| `cpp/measure_center.{h,cpp}` | **删掉 `projectWorld`**（夹 z 就在里面）；换成 `cameraIntrinsics()`。投影算法搬到 `slam_engine.cpp` |
| `cpp/slam_engine.cpp` | `getPinned` 重写：逐点算标记像素 + **逐段**用裁剪算两个端点 |
| `java/.../SlamBridge.kt` | 契约注释 |
| `java/.../MainActivity.kt` | 段那段变成「照着给的两个端点画线」；不再判任何 flag |

**新契约**（`8n + 1`）：

```
out[0] = n
每点 3 个：px py flags               bit0 在相机前方 / bit1 之后断开 / bit2 不太准
每段 5 个：x0 y0 x1 y1 len           **已经是画面上的两个端点**；len < 0 ⟹ 不画
最后 5 个：x0 y0 x1 y1 liveLen       橡皮筋；liveLen < 0 ⟹ 没有
```

## 决策

### 一、⭐ 契约：**每点一个像素**（甲）vs **每段两个端点**（乙）—— 用户选**乙**

（甲）是「每点一个像素 + 近端在前才画」，契约不变。**但它在数学上装不下所有情况**：

```
A ── B ── C        B 在相机后面

段 (A,B)：B 的像素是「沿 B→A 插值」来的 ⟹ 方向属于这一段 ✓
段 (B,C)：要用 B 的**另一个**方向（沿 B→C 插值）⟹ **那是第二个像素**
```

**⟹ 一个点只有一个像素，(B,C) 那条就画不出来。**

用户选**乙** —— 不为一条边牺牲正确性，代价是契约从 `4n` 变 `8n`。
**收益是 Kotlin 侧只剩「在两点之间画线」，一点几何都没有。**

### 二、**否决：「判断点在不在画面里」**（用户提的）

这个判据**不够**：**出画但还在相机前面的点，投影是准的、本来就画得好好的** ——
而「出画照样画」正是用户最早要的效果。真正该判的是**在不在相机平面之前**，
而**后面的点还必须算对方向**，「在不在画面里」两件事都答不上来。

### 三、顺带修掉一个判据错误

之前拿 `kMinZ = 0.05` **当相机平面用**，于是 `0 < z < 0.05` 的点（**在前，只是很近**）
也被当成「在后面」，走了那条错的近似。现在用 `z > 0` 分界：

```
z > 0     投（很靠近平面的点投出来很大，夹到 ±20000 就行）
z ≤ 0     才叫「在后面」
```

**出画 → 后面 的过渡因此是连续的**，不会在某个角度突然跳。

### 四、`kNearZ` 取多少**不影响正确性**

远端方向 `= (Dx/Dz, Dy/Dz)`，只跟两端有关 ⟹ `kNearZ` 只决定那个画外点**落在多远**。
取 0.02。

`defaultEnsure` 只在**值非法（NaN/Inf）**时抛 ⟹ **这次是 NaN**，来源待查。

## 遗留

- ⚠️ **标签会跑出屏幕** —— 标签画在两端中点，一端被推到画外时中点也在画外 ⟹
  **那条边的长度数字看不见了**。⚠️ 这个**原来就有**，但裁剪会把远端推得更远，更容易出现
- ⚠️ **`kMaxPinned = 128` 现在是硬上限** —— 到了就加不进去，而且**不会有提示**（UI 问题）
- ⚠️ **上面那个 NaN 崩溃**（不是这次的改动引入的，但也没修）
- **单向链 / 标签重叠 / 屏幕外不画标记** —— 老账，没动
