# 2026-10-14 2D 地图画中画 —— 里程碑 A（轨迹 + 当前位置）

一句话：**预览右上角多了一个 140dp 的小窗，画你走过的轨迹和当前的位置。**
SLAM 的产出**第一次有画面**（在这之前，屏幕上只有状态栏那一行「轨迹 N 点」）。

## 动机

APP_DESIGN 定的核心是「一条流水线、两个视图」，但**2D 地图整条腿一直缺着** ——
SLAM 一直在跑、地图一直在建，**一个像素都看不见**。

用户拍板的产品形态：**画中画** —— 预览全屏不动，地图缩在角落小窗常驻（140dp，右上）。

按 §5.4「从轨迹图起步」拆两个里程碑：**A = 轨迹 + 当前位置**（数据全在手、零新算法），
**B = 加点云 + 高度着色**（要动上游）。**这次只做 A。**

⚠️ **`xy` 就是地平面**这一点是核过的：APP_DESIGN §5.3 明写「重力对齐给的是 **Z 轴方向**」
⟹ 地面是 XY ⟹ 俯视图直接画 `x→右、y→上` ✓

## 决策

### 一、⭐ 抽稀**从前往后**，再补一个最新点（用户抓出来的）

第一版写的是「从**最新**往前每 k 个取一个」，理由是「保证含最新点」。

**用户一眼看出问题：那样每加一个点，整套采样点就挪一格** ⟹ 折线**每帧都在抖** ✗
比从前往后还糟（从前往后只在 `k` 变的时候才跳一次）。

**改成：**

```cpp
// 稳定网格 0, k, 2k, …  ← n 涨的时候这些点**不动**
for (int i = 0; i < n && m < maxPts - 1; i += k) { … }
// 再补一个最新点让线头贴着当前位置
if ((m - 1) * k != n - 1) { … }
```

**而且不会锯齿**：`n-1` 正好追上某个网格点时它**本来就是网格点**，下一个新点补在它后面
⟹ 线是平滑长出来的 ✓

**残留的抖动**：`k = ceil(n/512)`，n 每涨 512 个点 `k` 才 +1（30Hz 下约 **17 秒**一次），
跳一下在 5m 图上约 **7px** ✓ 可以接受。

### 二、⚠️ 这份契约和 `getPinned` **正好相反**，注释里专门写了别抄错

| | `getPinned`（折线）| `getTrajectory`（轨迹）|
|---|---|---|
| 要什么 | **精度** —— 每个点都得准 | **形状** —— 看清走过哪 |
| 多了怎么办 | **扩容，一个不能少** | **stride 抽稀，主动少给** |

**同一份代码库里两种相反的契约，因为要的东西不同。**
抄错了**不会报错**，只会白拷一堆没人看的点（或者丢精度）。

### 三、**不需要** `mapResetSeen`（计划里有，实现时发现多余）

计划说「地图重置时要立即 submit 空快照」，理由是「不能绑 `resetCountSeen`（那个只在测距开着时推进）」。

**这是对的，但不需要新状态** —— 重置时 **C++ 那边已经把 `traj` 清空了**（worker 的重置分支），
而 `getTrajectory` 是**无状态读** ⟹ 下一次读自然返回 0 ⟹ 图自己就空了 ✓
最多晚 250ms（一拍）✓ 看不出来。

### 四、hint **分四态**，不能合成一句

计划里是「slamState≠就绪 → "SLAM 未就绪"」。但 `slamState` 是四态，而**状态栏那边是分开的**
—— STAGE6 §2.7 说的正是**这一步要分开**（「加载中」和「没启动」混在一起，用户会去擦镜头）：

```
词袋加载中… / 构造失败 / SLAM 未启动 / 跟踪未就绪 / 等待定位… / （有轨迹就不显示）
```

### 五、折线用**白**，不用青

青色 `#00E5FF` 是**测量那边**标记和折线的颜色。同屏两块青会混 ✓ 改成白色。

### 六、⭐ 自查抓到一个真 bug：`Path` 是**累积**的

`onDraw` 里复用的 `Path` 如果只 `moveTo`/`lineTo` 而不 `reset()`，**每一帧都会往里再加一条折线**
⟹ 画面上越描越粗、旧轨迹永远擦不掉 ✗
**加一行 `path.reset()`** ✓（这种错不报错、也不是崩溃，只是画面慢慢变糟。）

### 七、朝向三角：**只挡除零，不挡「朝下」**（用户纠正的）

琥珀点只说明「你在哪」，不说明「你朝哪」⟹ 加一个小三角贴在点外面，尖端指**相机光轴在地面上的投影方向**。

**方向怎么算**：`poseBuf` 是 `Twc`（列主序）⟹ **第 3 列就是相机系 `+z`（光轴）在世界里的方向** ✓
取它的 `(x, y)` 归一化 ✓

**我一开始想加一条「太陡就不画」的启发式**（低头测地板时光轴的 XY 分量接近 0，怕方向乱转）。
**用户否掉了，而且他是对的：**

> 完全准确朝下这种情况几乎不可能

**低头时那点水平分量仍然是「方位角」** —— 晃 1° 方位角就动 1°，**是稳的** ✗ 我的担心不成立 ✗
只有**真的正下方**（水平分量恰好 0）方位角才无定义 —— **那是测度零** ✓

**⟹ 只挡除零**（`len > 1e-6f`），其余一律画 ✓

### 八、朝向三角**复用轨迹那条 `Path`**

一开始想另开一条，理由是「别互相踩」。**其实不用** —— 每次用之前都 `reset()` 了，
而且轨迹**先画完**才画三角 ✓ 一条就够 ✓

### ⚠️ 一条**这次没解决、要真机看**的

**轨迹会不会被 BA 带歪**：`traj` 记的是**每帧的实时位姿**，而**回环/全局 BA 会改写地图的关键帧位姿**
⟹ 录下来的点留在**旧坐标系**里 ⟹ 走过闭环之后，轨迹可能和当前位置**对不上** ✗

**这和「折线飘」是同一类病。** ORB-SLAM3 自己的 `SaveTrajectoryEuRoC` 不存绝对位姿、存的是
**相对关键帧**的位姿，读的时候重算 ⟹ 永远一致 ✓ 但那个是 **0.5s 一个点**（粗）。

**这次先按「细但有漂」做** —— 真机走一趟带闭环的路线，**歪得看不出来就这样**；
歪得明显再换成从关键帧重建。（140dp 的小窗，未必看得出来。）

## 遗留

- ⚠️ **上面那条「回环后轨迹会不会歪」没验**
- **里程碑 B（点云 + 高度着色）没做** —— 要动上游（`System.h` 加一行垫片）
- **auto-fit 每帧现算** ⟹ 地图会跟着你走而缩放（没有滞回）。真机上看着别扭再加
- **小窗不能点开/放大**（v1 无手势）—— 点它等于点预览
- **点数上限 512**（`kTrajExportMax`）—— 超了是抽稀，不是截断 ✓
