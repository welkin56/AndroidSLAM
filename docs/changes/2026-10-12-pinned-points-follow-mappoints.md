# 2026-10-12 折线的点改成**认住地图点** —— 刷新、投影、距离全搬到 C++

一句话：**折线不再存「按下那一刻的世界坐标快照」，改成存 `MapPoint*` 身份，每帧问它要最新坐标。**
顺带把刷新 / 投影 / 算长度**整件事**搬到 C++，Kotlin 只剩「照着缓冲画」。

## 动机

用户报的现象（真机）：

> 「它本来是在地板上的，但是我随便走了一下，他就变成这样了，**像是在空中一样**」

追问后得到三条决定性的观察：

| 实验 | 结果 |
|---|---|
| 站着不动，只慢慢转手机 | **不漂** —— 位姿是对的 |
| 走两米再回来 | **开始漂** |
| ⭐ **走完站定，看着它** | **还在不断漂** |

**第三条是判据**：站定时相机位姿静止，而投影还在动 ⟹ **动的是地图点，不是位姿。**

**根因**：折线存的是按下那一刻的**坐标快照**，而 **BA 一直在挪 `MapPoint`**（走路插的关键帧
还在被 LocalMapping 消化）。相机位姿跟着新地图走，快照留在旧地图里 ⟹ 错开。

**⚠️ 而且不只是「画得飘」—— 长度数字也是旧帧的。** 距离用的是冻结的坐标，
地图一优化那两个数就是错的，**而且看着很合理，不会有人发现**。

### 代码里其实早就写过这条教训

`measure_center.cpp` 实时读数那一路：

```cpp
// ⚠️ 用 `GetWorldPos()` 而不是环里的 `pw` —— 前者是最新的（BA 一直在动点）。
```

**实时读数每帧问地图点要最新坐标；折线用的是自己记住的那份。** 这次让它走同一条路。

## 改动

**核心：折线整件事搬到 C++**（只有 C++ 拿得到 `MapPoint*`）。

| 文件 | 改什么 |
|---|---|
| `cpp/measure_center.h/.cpp` | `CenterMeasure` 加 `ORB_SLAM3::MapPoint* mp`，路径 1 出结果时带上 |
| `cpp/slam_engine.h/.cpp` | `Engine::Pinned` + 五个接口；加 `#include "MapPoint.h"` |
| `cpp/jni_bridge.cpp` | `nativeProjectPoints` **删掉**，换成那五个 |
| `java/.../SlamBridge.kt` | 同上 |
| `java/.../MainActivity.kt` | 删掉 `Pinned`/`pinned`/`projIn`/`projOut`/`projectPinned()`/`dist()`；改成读缓冲 |
| `java/.../PreviewView.kt` | **一个字没改** —— `Overlay` 的契约没变 |

**存储**（`slam_engine.cpp`）：

```cpp
struct Pinned {
    ORB_SLAM3::MapPoint* mp = nullptr;  // 身份。nullptr = 平面兜底来的，没身份，只能冻着
    float pw[3] = {0,0,0};              // 兜底/失效时的坐标，也当每帧的刷新缓存
    bool low, startsChain, closed;
};
```

**数据契约（`nativeGetPinned`，每点 4 个 float）**：

```
px py flags lenToNext        + 最后一个 float：liveLen（最后一个点 → 十字；<0 = 没有）
flags 的位：1 在相机前方 / 2 新折线起点 / 4 之后断开 / 8 不太准
```

`getPinned` 每帧：**① 刷新**（`if (mp && !mp->isBad()) pw = mp->GetWorldPos()`）→
**② 投影**（复用 `projectWorld`）→ **③ 长度**。返回**实际写了几个点**（容量不够就少写）。

## 决策

### 一、⭐ **否决：测量期间暂停地图优化**（用户提的，值得记）

用户看到「`isBad()` 之后刷不动」，提议：**测距时暂停优化，不测时再优化。**

**技术上做得到** —— `System::ActivateLocalizationMode()` 就是干这个的（停掉 LocalMapping，
只留跟踪）。**但三条理由都不划算，第三条是决定性的：**

| | |
|---|---|
| **① 它不是风险点** | `isBad()` 的兜底是「留最后一份坐标」—— **不比原来更糟**，而且罕见 |
| **② 代价正好打在用法上** | 暂停优化 = **不三角化新点**。而用户是**边走边测**的：走到门边想测门框，那是刚进视野的区域 ⟹ **地图里一个点都没有** ⟹ 测不到 |
| ⭐ **③ 冻住的是「还没收敛的图」** | 点飘到**米级**（不是 BA 的毫米级微调）⟹ 是**回环/全局 BA 把整体尺度掰回来**了。**「飘」就是这张图在被修对的过程。** 暂停优化 = 冻住带误差的图 ⟹ **量的数字带着那个误差，而且不会告诉你** |

**⟹ 选「认住地图点」**：数字跟着地图一起被修正，**越量越准**。而且它顺带把长度数字也修对了。

> ⚠️ **由此带出一个要跟用户说清的现象**：数字会**自己慢慢收敛**
> （`1.379 m` 盯十秒变成 `1.352 m`）。**那不是抖动，是地图在收敛**，后一个更准。
> 想缓解可以加「地图正在优化」的提示 —— 那是**提示**问题，不是正确性问题。

### 二、**翻掉了「决策一」的一半**（对 [2026-10-11](2026-10-11-two-point-measurement.md) 的追加）

📌 上一份说「**会话放 Kotlin**」，立论是「距离是纯世界坐标的算式，所以 native 一个字都不用加」。

**现在 native 必须加**（`MapPoint*` 只在 C++ 侧拿得到）⟹ **立论没了，结论也不成立**。
而且链状态（`startsChain`/`closed`）本来就已经跟着过去了 ⟹ **Kotlin 手上关于
「哪两点连成一段」的信息一点不剩**，再把世界坐标喂回去让它算，才是真的割裂。

**⟹ 用户提的「C++ 把距离一起算了，别这么割裂」是对的** —— 而且契约还更小：

| | 原来的想法（世界坐标给 Kotlin） | 实际做的 |
|---|---|---|
| 每点 | 6 个 float（含 3 个世界坐标）| **4 个**（`px py flags lenToNext`）|
| n=20 总量 | 120 | 81（含 live 那个）|

### 三、`addPinned(snapTo)` —— 不做的话吸附会**变错**

「吸到已有点」原来的做法是复用那个点的**世界坐标**（两边一起冻着 ⟹ 一起漂，自洽）。
搬到 C++ 之后如果只是「把当前读数钉下去」，存的会是**十字当前命中的那个 `MapPoint`** ——
一个**不同的、只是碰巧很近**的点 ⟹ **两个点各漂各的**。

**⟹ 必须是「复制第 `snapTo` 个点的身份」**，所以有这个参数。

### 四、扩容策略：**保持余量**，不是「满了才扩」（用户纠正的）

我第一版写 `if (pinnedN * 4 + 1 >= pinnedBuf.size) 扩容`。

**⚠️ 它在 `size` 不是 `4k+1` 时会静默卡死**：`size = 32` 时那个不等式等价于
`pinnedN >= 8`，而 C++ 最多只写 `(32-1)/4 = 7` 个 ⟹ **永远不扩容，永远少画几个点**。

**用户指出后改成「余量掉到 8 个点以下就扩」** —— 这样**根本不走到截断那条路**，
而且不怕这种 off-by-one。

### 五、顺带：`segLabels` 的缓存策略必须改

长度**现在每帧都在变**（地图在收敛），「只在点变了时算」的缓存会过期。
改成**每帧比一次、变化超过 0.5mm 才重新 `format`** —— 显示到毫米，比这更小的抖动
不该让字符串重排（那只会让标签闪）。每帧代价只剩一次浮点比较。

### 六、⭐ 复查时才发现的：**叠加层 15fps，但喂它的数据还是 4Hz**

`buildOverlay()` 在 `onDraw` 里跑（15fps），但它读的 `measureBuf` 是 `pollMeasure()`
在 **250ms 的 ticker** 上填的 ⟹ **标记平滑、琥珀吸附圈和橡皮筋另一端一秒跳 4 次**。

**这正是用户之前报的「线跟不上画面」的同一个病**，只是被我从「全部 4 Hz」改成了
「一半 15 Hz」—— **更难看了**。修法是 `buildOverlay` 里也读一次测量（`readMeasure()` 提取出来）。

## 遗留

- ⚠️ **平面兜底来的点（`mp == nullptr`）仍然只能冻着** —— 没身份就没得刷新。
  标着「不太准」（空心圈），但**走久了会飘**
- ⚠️ **地图点被剔成 `isBad()` 之后也刷不动了** —— 留最后一份坐标。罕见，但不为零
- ⚠️ **截断那一帧的 `liveLen` 是从「最后一个写下的点」算的**，不是真正的最后一个。
  和画面一致（画也是画到那儿），但不完整。保持余量之后正常走不到
- **`MapChanged()` 的提示**没做 —— 有了刷新之后它从「正确性问题」降成「UI 提示」
- **点数没有上限** —— 一直加就一直存
- **单向链 / 标签重叠 / 屏幕外不画标记** —— 上一轮的老账，没动
