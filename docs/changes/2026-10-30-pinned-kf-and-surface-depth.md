# 2026-10-30 钉点改成「关键帧刚体 + 点–面深度约束」

一句话：钉点不再存「某个地图点的世界坐标」，改存**锚点关键帧相机系里的一个位置**，
**整条链共用一个关键帧**（所以整条链是刚体）；深度由**局部平面**约束，钉下之后还会继续收敛；
整图尺度修正时 `p_kf` 一起重标，标记不再脱面。

> 上一版（把每个点绑到各自地图点的参考关键帧）已回滚，本文是从 `da6a900` 重做的。

## 动机

用户报：两点距离量完，**走一圈回来数变了**（实测 1.113 → 1.559 m），**标记也和标的位置偏了一点**；
左右晃手机时读数也会动一点。

排查下来是**两条互不相干的通道**，上一版只碰了其中一条：

**① 非刚体修正。** 单目对一个地图点的深度只约束到一条射线上 —— 沿射线滑动，重投影误差
几乎不变（`δZ = Z²·δd/(f·B)`，2 m、10 cm 基线时 1 px ≈ 9 cm）。所以那个方向没有信息，
BA 只会把它推来推去。日志里「点 1 一秒 +37 cm」就是它。

**② 整图尺度修正。** `LocalMapping::ScaleRefinement()`（`LocalMapping.cc:1431`）在
`mTinit` 落在 **25/35/45/55/65/75 秒**的 0.5 s 窗口内、且关键帧 ≤ 200 时触发，
`|mScale-1| > 0.002` 就 `ApplyScaledRotation(Tgw, s)`；两次 `InitializeIMU`（VIBA）末尾也走这条。
它把**所有关键帧的相机中心 ×s、所有地图点 ×s** —— 尺度是单目里唯一看不见的自由度，
**投影完全不变**，只有米数变。这和「数变了、标记却没怎么偏」精确吻合。

上一版的两个问题：

- 每个点跟着**自己的**参考关键帧 ⟹ 两点骑在两个刚体上，局部 BA 照样能改写段长；
- `p_kf` 是不变量，`ApplyScaledRotation` 之后**没跟着乘 s** ⟹ 由
  `pw = R_wc·p_kf + s·O_kf` 得 `pw_new − pw_old = (s−1)·O_kf`：每个点按**它那个关键帧
  离地图原点多远**整体平移，两点朝不同方向散开。走出 3 m、s 差 3%，就是 9 cm。

## 改动

**`thirdparty/orb_slam3/include/Map.h`、`src/Map.cc`**

- 加 `std::atomic<float> mMetricScale`（构造为 1）和 `GetMetricScale()`。
  `ApplyScaledRotation` 末尾 `mMetricScale *= s`，并打一行 `[MAP] 尺度修正 s=… 累积=…`。
- 用 atomic 是为了 `getPinned` 在 60 fps 下读它不去抢 `mMutexMap` ——
  `ApplyScaledRotation` 会抱着那把锁遍历整张图。

**`cpp/measure_center.h`**

- 加 `SurfaceDepth`（`ok / ratio / inliers / total / residual / cosInc`）和 `surfaceAtPoint()`。
  接口仍然不出现 `cv::` 和 Eigen，因为 `slam_engine.cpp` 不链 OpenCV。
- `CenterMeasure` 加 `int surface`，日志用。

**`cpp/measure_center.cpp`**

- 把 `planeDepthAt` 拆成 `fitPlaneAt`（拟合 + 统计，可指定任意像素和半径）+ `planeDepthAt`
  （原来的兜底路径，行为不变）。
- 新增 `correctDepth()`：**沿射线把点缩放到局部平面的深度，横向不动**。
  门控：内点 ≥ 8、内点率 ≥ 80%、1/Z 域残差 RMS < 2%、入射角 < 60°；
  另外平面深度与原深度差超过 50% 时**拒绝修正**（那说明平面锁到了别的表面上）。
- `centerMeasure` 的输出段调用它，只改 `distance` 和 `wx/wy/wz`；
  **锁定 / 深度跳变那套状态机继续用未修正的 `pc`**，判据一个字没变。
- 新增 `surfaceAtPoint()`：给外部按世界坐标修正深度，返回 `ratio`。

**`cpp/slam_engine.cpp`**

- `Pinned` 改成 `{ mp, kf, p_kf[3], sAtPin, pw[3], low, startsChain, closed }`。
- `addPinned`：`snapTo` 复制；新点优先继承**上一条未断开链的 `kf`**，起新链时才
  `mp->GetReferenceKeyFrame()` 并 `SetNotErase()`。`p_kf = Tcw(kf) * pw`。
- `refreshPinned`：先按 `GetMetricScale()` 把 `p_kf` 重标，再由 `kf->GetPoseInverse()` 算 `pw`。
- 新增 `refinePinned()`（SLAM 线程，`orbTrack` 之后、每帧一个点轮流）：
  `surfaceAtPoint` 拿到 `ratio` → `pwNew = Rwc·(ratio·pc) + cam` → 换算进锚点关键帧 →
  **EMA（α=0.15）**写回 `p_kf`。
- `undoPinned` / `clearPinned` 释放关键帧保护；`maybeRestoreMap` 换图时 `clearPinned()`。
- `getPinned`：① 改成 `refreshPinned(p)`，段长仍是 `dist3(pw_i, pw_j)`（同 KF ⟹ 天生刚体）。

**`java/.../MainActivity.kt`** — 段标签 `%.3f m` → `%.2f m`，重排阈值 0.5 mm → 5 mm。

## 决策

**① 整条链共用一个关键帧，而不是每个点跟自己的。**
两点各骑一个刚体时，段长是两个独立位姿的函数，局部 BA 一改就变 —— 这是上一版的漏洞。
共用之后 `dist3(pw_i, pw_j) = |p_kf_i − p_kf_j|`（同一个 R 作用在两端），**结构上就不可能是非刚体**。
代价是链拉长后锚点变远、杠杆放大，见「遗留」。

**② `p_kf` 必须跟着尺度重标。**
`p_kf` 不变，而 KF 的平移被乘了 s，两边就不是同一个尺度了：点是冻住的，图是被缩放的。
乘上之后 `pw_new = s·(R·p_kf + O)`，与地图点完全一致。这是**确定的 bug 修复**，不是优化。

**③ 平面只当约束，不当答案。**
单点的问题是**零空间**（沿射线无信息），不是噪声；平面正好把这个方向补掉，
`1/Z = a·u + b·v + c` 在像素上是严格线性的（平面 `n·X=1` 代 `X=Z·r̂` 即得），
3×3 正规方程闭式可解。
但**不能把 `planeDepthAt` 的返回值直接当深度**：它的失效模式是**偏差**——
十字压在桌沿、门框、曲面上时，96 px 圆盘里混了两个面，会给出一个「看起来合理」的中间值，
而且是外推（用整个盘估中心那一点）。偏差比噪声难发现得多。
所以只取它的**深度**，横向位置仍然由锚点自己的像素决定：**单点给身份，平面给深度**。

**④ 沿射线缩放，不是只改 z。**
`pc = Z·r̂`，只把 z 换成平面深度会连方向一起改掉（`(x,y,z)` 里改 z 等于换了一条射线）。
乘 `ratio = Z_plane / Z` 才是「沿原射线滑到那个深度」。

**⑤ EMA 而不是直接赋值。**
地图本身还在收敛，刷新目标是动的；直接赋值会让读数跳。α=0.15、每帧一个点，
约 0.5 s 爬过去。走开之后没有观测，EMA 自然停。

**⑥ `centerMeasure` 的状态机一个字没动。**
锁定（`locked`）、深度跳变判定、支持度统计继续用**未修正**的 `pc`，`lastD` 也存未修正值。
只改发布出去的 `distance / wx / wy / wz`。那套判据是之前几轮真机调出来的，
没有理由为了一个新特性去动它。

**⑦ 否决：把段长冻结成常量。**
「钉下即定」看着最稳，但那是**拿准确性换稳定性**：尺度修正带来的信息被丢掉，
读数永远停在钉点那一刻的误差上。用户明确说「更需要它准」。
现在的做法是：看得见它的时候按 EMA 慢慢收敛（每次几毫米），**走开之后完全静止**，
尺度事件发生时整体重标 —— 该动的动，不该动的不动。

**⑧ 否决：把 `planeDepthAt` 提成主路径。** 见 ③。

## 遗留

- **`±` 没做。** 要改 `getPinned` 的 JNI 布局（现在是 8n+1），这一轮不动。
  没有 `±`，用户没法判断某一次读数能不能用。
- **锚点用 `GetReferenceKeyFrame()`，没有按观测数投票。** 更贴的做法是统计面片里那些点
  被哪些关键帧看到，取最多的那个。要遍历 `GetObservations()`，等这一版稳定再换。
- **链变长时锚点离得远**（> 4 m 后杠杆明显）。现在不做自动断开，
  因为断开会丢一段测量；先在日志里看实际链长。
- **平面假设**：曲面、树叶、玻璃、两层景物靠门控挡掉 —— 挡掉就等于没有提升，
  退回单点。这类目标上「+40%」那种粗差不会回来，但也不会有 1–2% 的精度。
- **已知长度校准没做。** 尺度误差（1–3%）仍是误差预算里最大的一项，而它是个标量，
  一次校准就能砍掉。这是下一步收益最大的事，纯应用层，不动 SLAM。
- **IMU–相机杆臂仍是 0**（`phone.yaml:72`），转动位姿有 1% 量级偏差，未处理。

## 追加：第一轮真机结果 + 二轮修正（同日）

### 真机跑出来的事实

| 项 | 结果 |
|---|---|
| 钉点日志 | ✅ 锚点非 0，同一链确实共用同一个关键帧（180 / 395） |
| `深度面` | ❌ **0 / 146**，点–面这条路整条是死代码，`refinePinned` 从未写过 `p_kf` |
| 候选密度 | 30 px 锥内中位 **2–3** 个，最大 7 ⟹ 64 px 盘推算只有 10–14 个 |
| 场景 | 跨度 251% / 232% / 253%，前后两三层 |
| `ScaleRefinement` | ✅ 出现，但**比文档写的频繁**：它按关键帧调用，同一个 0.5 s 窗口内会触发 2–3 次 |

三条更正：

1. **「每 10 秒一次」是错的。** 窗口是 25/35/45/55/65/75 s，但窗口内**每来一个关键帧就跑一次**。
   实测 42.1 / 42.4 两次、53.1 / 54.0 / 56.1 三次。
2. **`累积` 不是误差指标。** 建图时单目尺度是任意的，0.68 那一下是 IMU 初始化把它定到米制；
   累积值只说明「离最初那个任意尺度差多远」。真正要看的是**两次事件之间**的净变化
   （实测钉 #1 到钉 #2 之间 −0.94%）。日志里的字段名已从「累积」改成「图尺度」。
3. **「段长稳住了」第一轮验不了** —— 版本里没有每秒的段长日志，只有钉点那一刻的 `p_kf`。

### 二轮的三个改动

**① `Map* mapAtPin`（bug 修复，优先级最高）**
`refreshPinned` 原来用 `p.kf->GetMap()->GetMetricScale()` 算比值。但 `Map::clear()` 会把
关键帧的 `mpMap` 置空、合并时 `UpdateMap()` 会把关键帧挂到另一张图上，而那张图的
`mMetricScale` 是它自己的历史 ⟹ 比值是垃圾：`s=1`、`sAtPin=0.44` 时 `p_kf` 被乘 **2.27 倍**，
钉点瞬间飞走。
现在 `Pinned` 记 `mapAtPin`，`p.kf->GetMap() != p.mapAtPin` 就**不重标、标 `low`、冻住**。
清图 / 换图 / 合并三种情况都走这条，永不算比值。

**② 段长心跳（1 Hz）**
`logSegments()` 在 `refinePinned` 里限流 1 Hz：

```
[M6] 段长 1.203 1.556 | 锚点 180 180 395 | 图尺度 0.9943 | 点 3
```

这是唯一能证明「读数稳住了」的东西，别的都是推理。断链处打 `-`。

**③ 门控放宽 + 中间量日志**

| 参数 | 原来 | 现在 | 理由 |
|---|---|---|---|
| 半径 | 64 px | **96 px** | 面积 2.25×，候选数翻倍 |
| 内点下限 | 8 | **6** | 密度不够，8 不可达 |
| 内点率 | ≥80% | **删掉** | 和 `fitPlaneAt` 内部「内点过半」重复，且是最难过的一道 |
| 残差 RMS | 2% | **4%** | 4% × 2 m = 8 cm，可接受 |
| 入射角 | cos ≥ 0.5 | **cos ≥ 0.3**（72°） | 桌面、地板基本是掠射，0.5 把它们全挡了 |
| 锚点与平面一致 | ≤ 50% | **≤ 25%** | 见下 |

诊断行（1 Hz 限流，带 tag 区分是十字还是钉点）：

```
[M6] 面[十字] 候选12 内点4 残差3.2% 入射0.71 深度2.13→2.05 拟合失败
```

`拟合失败`（点够但不共面）也打，否则它静默地什么也不发生，看起来和「全部通过」一样。
`fitPlaneAt` 的两个 `inliers/residual` 赋值提前到「内点过半」判据**之前**，
不然失败时这两个数永远是 0，诊断只剩一句「失败」。

### 决策：为什么用「与锚点差 25%」取代「内点率 80%」

内点率想表达的是「这块邻域是一个可信的干净平面」。但在两三层景物的场景里，
60/40 的混合永远过不了 80%，而 60% 那一层可能是真的、也可能不是。
真正要问的不是「平面干不干净」，而是**「这个平面是不是经过我量的那个点」** ——
所以改成：平面允许不够干净，但**锚点自己必须落在这个平面上（差 ≤ 25%）**，
否则分不清谁错，不改。这样既放过了稀疏场景，又不会让一个背景平面把点拖走。

### 验证（第二轮真机，2026-10-30 20:22–20:25）

真值（用户用砖块摆的）：**1.2 m 和 0.4 m**。

| 项 | 读数 | 误差 |
|---|---|---|
| 段 1 | 1.099 → **1.171** | −8.4% → **−2.4%**（2.9 cm） |
| 段 2 | 0.480 → **0.398** | **−0.5%**（0.2 cm） |

三条结论：

1. **刚性链成立**：`图尺度` 全程 4.1652 未变，段长在 20:23:50 之后 **90 秒一位不动**。
2. **点–面修正方向是对的**：段 1 从 −8.4% 被拉到 −2.4%，走了 90% 的路 ——
   说明单点初值的深度确实偏短，平面给出的方向是准的。这也反证 ③ 的判断。
3. **误差不是纯尺度**：如果只是米制尺度偏，两段应同比例偏。实际 −2.4% / −0.5%，
   说明段 2 那 0.4 m 上的尺度误差只有 **0.5%**，多出来的 1.9% 是段 1 端点的深度残差。

**但收敛是台阶式的**：1.088 → 1.115 → 1.171 用了 5 秒、两次跳。因为
`面[钉点]` 的成功率极低（155/156 失败），成功那几次一步到位。
⚠️ **不能单独把 α 调小** —— 成功率本来就低，降 α 只会让收敛慢到分钟级。
两个参数必须和「选层」一起改。

**点–面为什么全失败（这条最重要）**：`候选 10~143，内点恒为 0，入射 0.00` ——
不是门控挡的，是**第一次全量最小二乘在多表面窗口里拟合出的平面，把所有点都判成了外点**。
96 px 在 2 m 处横跨 ±0.6 m，一个墙角就够毁掉它。**继续放宽阈值无效，要先选层再拟合**
（按锚点深度 ±30% 预筛，必要时加一轮自适应残差门）。这条留作下一轮。

### 遗留（本轮新增）

**测量侧**

- **平面拟合必须先选层，再拟合。** 现在是把 96 px 窗口里的点做一次全量最小二乘，
  多表面窗口里这个"妥协平面"谁都不贴，内点剔除会把**所有**点判成外点
  （实测 155/156 次 `内点0 残差0.0% 入射0.00`）。继续放宽阈值无效 —— 平面本身是错的。
  做法：按锚点深度 ±30% 预筛，必要时再加一轮自适应残差门。
- **`kSurfRelMax`(25%) 和 `kRefineAlpha`(0.15) 未调。** ⚠️ 不能单独降 α：
  成功率本来就 1/156，降 α 只会把收敛从 5 秒拖到分钟级。两个参数必须和「选层」一起改。
- **段长收敛是台阶式的**（1.088 → 1.115 → 1.171，5 秒两次跳）。选层之后成功率上来，
  才会变成平滑收敛。
- **长链重锚没做**：整链仍挂在一个关键帧上，链长了远端标记的绝对位置靠杠杆推断
  （段长不受影响）。等平面活过来再看要不要做。
- **`seen` 环没有当作点源**：它是时间序列不去重，256 槽里只有 5–10 个不同的点，
  要当点源得先按 `mp` 去重再投影，去重后约 10–30 个（2–3×，不是先前说的 5–10×）。
  去重后 `kMinSupport` 的语义会变，必须一起重定。
- **`±` 不确定度没做**：要改 `getPinned` 的 8n+1 布局。

**跟踪侧（这轮暴露出来的，不在本改动范围内）**

- **[a] 低置信时冻结标记 —— 只改显示，不动 SLAM。**
  现象：跟踪飘的时候标记跟着位姿一起跑远，看起来像测量坏了，其实错的是位姿。
  做法：`refinePinned` 里本来就拿了 `GetTrackedMapPoints()`，顺手数非空数量；
  低于阈值（拟 40）时在 `Engine` 上置一个 `poseWeak` 标志，`getPinned` 见到它就不调
  `refreshPinned`，沿用上一份 `pw`。标记停在原地，等跟踪恢复再继续。
  ⚠️ 必须同时把 `low` 置上、界面给个明确状态，否则用户分不清「卡住」和「坏了」。
- **[b] 上游「丢一次就清图」改成连续失败才清。**
  `Tracking.cc:2163`：`!isImuInitialized() || !GetIniertialBA2()` 时，跟踪丢一次就
  `ResetActiveMap()`。实测 40 秒内清了 **7 次**，每次坐标系重锚 —— 这是「地图跳一下 /
  漂一段」的直接来源。改法：加连续失败帧数 / 丢失时长计数，超过 N 帧或 T 秒再清。
  ⚠️ 动 `thirdparty`，要单独评估：清图是上游对「单目惯性还没收敛就乱跑」的保护，
  放宽前得先确认不会把带误差的图固化下来。
- **采集页对焦未确认。** 实测 96 px 锥内 `纹理` 只有 4–32（正常应 ~90 以上），
  同时段出现过一次 267，10 倍落差更像**失焦**而不是白墙。标定页锁了自动对焦，
  采集页没有。先看预览画面糊不糊，再判断是场景问题还是对焦问题。

## 追加：`SetErase` 的空指针路径（2026-10-31）

### 成因

`clearPinned` / `releaseKfIfUnused` 会调 `KeyFrame::SetErase()` 解除钉点保护。
但 `SetErase` 不是纯解锁 —— `mbToBeErased` 已置位时它会直接进 `SetBadFlag()`，
而 `SetBadFlag()` 第一行就是：

```cpp
if(mnId==mpMap->GetInitKFid())    // KeyFrame.cc:577
```

`Map::clear()` 会把每个 KF 的 `mpMap` 置成 NULL（`Map.cc:246`）。所以
**地图被重置之后再清空折线 → `mpMap` 已经是 NULL → 空指针解引用**。

`mbToBeErased` 是**粘性**的：`KeyFrameCulling` 只遍历当前 KF 的共视邻居
（`LocalMapping.cc:910`），一个钉点时的 KF 在随后几秒内被判冗余、被
`SetNotErase` 挡下、打上标记；它离开共视范围之后就再也遍历不到，这个标记
就一直留着，没有任何东西会清它。

### 但触发窗口很窄：只在开局前 15 秒

`ResetActiveMap` 才是走 `Map::clear()` 的那条路。其余路径都不置 NULL：

| 入口 | 条件 | `mpMap` |
|---|---|---|
| `Tracking.cc:2188` | IMU 已初始化 且 `!GetIniertialBA2()` | **NULL** |
| `Tracking.cc:2307` | `LOST` 且 `KeyFramesInMap() <= 10` | **NULL** |
| `Tracking.cc:1841` | `mbBadImu`（`mTinit < 10` 且几乎没位移） | **NULL** |
| `Tracking.cc:2311` / `2057` | 其余丢失 → `CreateMapInAtlas()` | 仍指向旧 Map |

而 `SetIniertialBA2()` 在 `mTinit > 15.0f` 时就被置上（`LocalMapping.cc:219`，
**在 VIBA2 真正跑之前**）。所以前两条的窗口只有建图后的前 15 秒。
`mTinit` 还要求相机中心位移 > 5 cm 才累加（`LocalMapping.cc:136`），
所以站着原地转能让这个窗口保持得更久。

⟹ **正常用法（建图 30 秒后钉点）碰不到。** 这条不是「随时会炸」，
是「开局十几秒内钉过点、又丢过跟踪、再清空」才会炸。

### 改了什么（只加判断和日志，不改行为）

| 位置 | 改动 |
|---|---|
| `slam_engine.cpp:1022` `releaseKfIfUnused` | `if (kf->GetMap() == nullptr) return;` |
| `slam_engine.cpp:1188` `clearPinned` | 同上，另外累计 `stale` 个数打一行 |
| `KeyFrame.cc:583` `SetBadFlag` | `mbNotErase` 分支首次命中时打 `[KF] 保护命中 KF=N` |

**没做**的两件事，写清楚以免以后又被当成遗漏：

- **没有放弃 `SetErase()`**。那样能一并消掉跨线程 `SetBadFlag`，但会让每条链
  的锚点 KF 永久保护、永不剔除，反复清空重钉会累积到上千个，地图越跑越重。
  用一个更大的隐患换一个小隐患，不划算。
- **没有把解除保护挪到 SLAM 线程**。worker 和 LocalMapping 仍是两个线程，只是
  把 UI 线程换成 worker，没根治；而 `SetBadFlag` 内部锁齐全、上游
  `MapPoint::SetBadFlag` 本来就是多线程调的，为这条窄路径引入队列 + drain
  不值得。

### 验收

不需要专门设计场景，正常用一次即可，看两行日志：

```
[KF] 保护命中 KF=436                                    ← culling 想剔它，被钉点挡住
[M6] 清空折线：1 个锚点KF 已随旧图失效，跳过解保护        ← mpMap 真的是 NULL
```

两个都出现、id 对得上，就说明原本的崩溃路径确实可达（而且已经被挡掉）。
`[KF] 保护命中` 一次都不出现，说明这条路径在实际使用里进不去，可以从遗留划掉。

### 回滚

删掉那三行判断和两行日志即可，没有格式变更、没有状态。

⚠️ 这条是**代码审查得出的结论，没有真机复现**。`mbToBeErased` 在 `protected`
区且没有 getter，外部读不到，所以加了日志来替代观测。

## 追加：第三轮真机 —— 点–面仍没生效，而且日志本身测不出来（2026-10-31 21:19）

### 观测

- **`[KF] 保护命中` 出现了，共 7 次**（KF 73 / 180 / 256 / 294 / 295 / 479 / 184）。
  说明 `SetErase` 那条空指针路径的前置条件（`mbToBeErased` 挂上）确实会发生，
  上一轮的代码审查结论成立，防御是必要的。
  （`[M6] 清空折线` 没出现 —— 那几次没有在「地图被重置」之后清空折线，所以没走到。）
- **点–面约束一次都没真正改过深度。** 151 条 `面[...]` 里只有 1 条「通过」，
  而那条是 `深度 1.93→1.93`（ratio ≈ 1.000）—— **等于没改**。
  其余 150 条全是 `内点0 残差0.0% 入射0.00 拟合失败`。
- **段长：同一块 1.2 m，三次读数 1.099 / 1.171 / 1.247**（−8.4% ~ +3.9%）。
  刚性链本身是可靠的 —— 21:19 那次 1.256 挂住 11 秒一位不动，只在尺度事件
  s = 0.993 时同步变成 1.247（比值 0.9928，与 `图尺度 1.4426→1.4325` 精确对应）。
  **摆动全部来自端点深度，不是链。**

### 一个必须先修的可观测性缺陷

`logSurface()` 的「十字」和「钉点」两个 tag **共用一个 `static lastMs`**，是 1 Hz 的**全局**限流。
而 `correctDepth` 每帧都在调（十字 15~30 Hz，钉点每帧轮转一个）。
所以日志里那 150 条只是**抽样**，真实调用率高一个数量级，**成功率根本算不出来**。

⟹ 先给两个 tag 各自一个计时器，才能判断「多表面窗口失败」到底占多少。
（`面[钉点]` 每帧最多一次，可以只限到 2 Hz。）

### 结论没变，但更确信了

`fitPlaneAt` 先做全量最小二乘、再按 5% 剔外点，在多表面窗口里必然把所有点判成外点 ——
这条上一轮已写进遗留（「必须先选层，再拟合」）。

这一轮的新信息是：**唯一成功的那次，恰好是单表面窗口**（内点 35/37、残差 1.9%、入射 0.60）。
算法本身没坏，坏的是喂进去的样本。这也解释了为什么继续放宽阈值无效 ——
放宽只会让「妥协平面」收进更多点，然后给出一个看起来合理的错值。
