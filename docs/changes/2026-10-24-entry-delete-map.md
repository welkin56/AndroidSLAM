# 2026-10-24 入口页删除地图

一句话：首页地图卡片**长按** → 确认弹窗（列出这个目录里都有什么、多大）→
删掉**整个会话目录**（`.osa` + `map-<id>/` 轨迹 + `rec/` 录像），列表就地刷新。

## 动机

保存过的地图只能在 `adb shell rm` 里清。入口页列表是只读的：能看、能选，
删不掉。重启 App 不会清，`.osa` 只会越攒越多。

## 改动

- `EntryActivity.kt`
  - `mapTitle()`：把「文件名与目录名重复时只显示目录名」抽出来，列表和弹窗共用。
  - 卡片 `setOnLongClickListener`：`askDeleteMap()`。
  - `askDeleteMap()`：确认弹窗；正按钮递归删目录，成功后 `refreshMapList()`；
    失败 `Toast` + 日志，列表不刷新。
  - `summarize()`：目录粗统计 —— 地图份数、轨迹条数、录像文件数、总大小。
  - `deleteRecursively()`：`File.delete()` 不递归，自己走一遍。
  - `refreshMapList()` 同步 `tvListHint` 的显隐。
- `activity_entry.xml`：「已保存的地图」标签行换成 `LinearLayout`，
  右侧加 `tvListHint`「长按删除」；空列表时跟列表一起收起。
- `item_map.xml`：注释里的点击行为补上「长按删除」。

## 决策

**① 删整个会话目录，不单删 `.osa`。**
一行地图背后其实是一个目录：地图本体、按图归档的 `map-<id>/` 轨迹、`rec/` 录像。
只删 `.osa` 会让这个目录从首页消失，但数据还在磁盘上 —— 用户再也无法从 App 里清掉它，
只能抠 `adb`。整目录删才是「删掉这张地图」的完整含义。用户确认过这个口径。

**② 长按 + 确认弹窗，不做行内垃圾桶、不做左滑。**
用户选的。列表保持干净，删除是低频动作，不值得每行常驻一个红色目标。
长按不可发现，所以在分区标题右侧挂一行「长按删除」；列表为空时收起，
空状态下没必要提示一个不存在的动作。

**③ 弹窗先算账再删。**
录像可能有几百 MB，只说「删除后不可恢复」不够，要说清**丢了什么**：
`1 份地图 · 3 条轨迹 · 12 个录像文件 · 240 MB`。统计是全目录扫一遍，
文件数量级很小，主线程扫没有负担。

**④ 同一目录里的多份 `.osa` 一起删，弹窗明说。**
列表按文件平铺，一个目录可能出多行（另存/多次保存的残留）。删其中一行会带走整目录，
所以弹窗补一句「目录里另外 N 份地图也会一起删掉」。这是唯一会「删一行掉多行」的情况。

**⑤ 删除失败不吞。**
`deleteRecursively` 返回 false 时提示「删除失败，详情见日志」，并且**不刷新列表** ——
部分删除后的状态照实暴露，不要装作干净了。

**⑥ 长按不震动**（用户口径），只靠弹窗本身作反馈。

**⑦ 不需要担心「删了主界面正在用的那张图」。**
`MainActivity` 的返回键走默认行为（`finish()`），所以入口页可见时，主界面必然已经销毁。
跨页状态问题在这里不存在。

**否决：**
- **只删 `.osa`。** 留下首页看不见、App 里也删不掉的孤儿目录。
- **弹窗里勾选「连轨迹和录像一起删」。** 多一步选择；不勾的那个分支仍然是孤儿数据。
- **行内删除图标 / 左滑删除。** 见 ②。
- **回收站 / 撤销。** 目录里可能躺着几百 MB 录像，撤销要先把数据挪走，收益不值。

## 遗留

- **不可恢复**：没有回收站，也没有撤销。
- **主线程递归删除**：文件数不多，但几百 MB 的录像 `unlink` 可能要一点时间，
  期间没有进度提示。真机上感觉卡再考虑挪到后台线程。
- **删除不校验任何持有者**：见决策 ⑦，当前没有「入口页可见 + 主界面活着」的状态。
  以后若改掉 `MainActivity` 的返回行为，这条要重看。
- **不做整目录的外科手术**：不能只删 `rec/` 留地图，也不能只删地图留录像。
