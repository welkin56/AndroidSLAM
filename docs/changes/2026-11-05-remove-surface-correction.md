# 2026-11-05 平面深度：删修正链，保留兜底并补门控

## 动机

`dev` 上一直有两段被当成一件事的代码：**修正链**（用局部平面改已有地图点的深度）
和**兜底链**（十字没锁到点时用平面估一个深度）。它们共用同一个 `fitPlaneAt`，
所以也被同一个 bug 一起废掉。

11-05 的 dev 日志（5 分钟）把这个状态摊开了：

```
[M6] 面[...]           242 条，全部是「拟合失败」，通过 0 次
路径1（地图点）        228 次
路径2（平面兜底）        0 次
[M6] * 测不到          110 / 338 = 32.5%
```

根因和 11-04 在 `exp/surface-depth` 上定位的一样：`fitPlaneAt` 用 `Matrix3f` 拿
**绝对像素**（u≈320、v≈240）建正规方程，法矩阵条件数约 2.6e7，float 的秩判据
`3·ε·maxpivot` 把最小特征值判成 0，`FullPivLU::isInvertible()` 直接返回 false。
**第一次最小二乘从来没出过解。**

11-04 那次实验已经证明数值修好后修正链是净负提升（段长极差 0.5% → 8~23%，
修正比中位数 1.000 / 0.976 摇摆，没有稳定的系统偏差可修）。但那一次
**兜底也一起被修好、而且没有门控**，用户撤销删除并反馈「读数更不准」——
两种东西混在一次改动里，无法判断是谁的问题。

所以这次的目标是：把两条链拆开，各自按自己的证据处理。

## 改动

- `app/src/main/cpp/measure_center.cpp`
  - `fitPlaneAt`：坐标改成**相对目标像素**的 `(du, dv)`，正规方程与求解改用 `double`。
    平移后最小特征值从 0.13 量级升到 27 量级，秩 3 成立。这是唯一能解开方程的前提，
    兜底要靠它才能工作。
  - 删除 `correctDepth` 整个函数（沿射线缩放深度、改 `p_kf` 的那条链）。
  - 删除 `kSurfRadiusPx`（只服务于修正链）与 `kSurfRelMax`（修正量的限幅）。
  - `planeDepthAt`：加上和原修正链同一套门控（内点 ≥6、残差 ≤4%、入射角 cos ≥0.3），
    并把三档失败原因打进日志（`内点少` / `残差大` / `掠射` / `拟合失败`）。
    原来它只有「内点过半」一道判据。
  - `logSurface`：去掉 `zNew` 参数。兜底不修正，`z → z` 那一栏永远同值。
- `app/src/main/cpp/measure_center.h`
  - 删 `SurfaceDepth` 结构、`surfaceAtPoint()` 声明、`CenterMeasure::surface`。
  - `CenterMeasure.wx/wy/wz` 的注释改成「method == 2 时是主点视线估算，只能显示、不能钉」。
    原注释写「method == 2 时无效」是错的——兜底路径确实填了这三个字段。
- `app/src/main/cpp/slam_engine.cpp`
  - 删 `refinePinned()`、`kRefineAlpha`、`kRefineMinZ`、`Engine::refineCursor`。
  - worker 里原来的 `if (r.valid) refinePinned(...)` 换成持 `measureMutex` 调
    `logSegments(e, nowMs())`。**段长心跳原来寄生在 `refinePinned` 里**，
    直接删会让每秒那条 `[M6] 段长` 一起消失，而它是验收测距唯一的时间序列。
  - `addPinned`：`method != 1` 或 `mp == nullptr` 时直接拒绝。兜底读数没有地图点身份，
    坐标是按主点视线算的，钉下去等于把平面误差带进段长。

## 决策

- **采用：删修正链，不留开关。** `exp/surface-depth` 里那版用 `kSurfaceApply = false`
  把功能关掉保留代码，但关闭状态下 `correctDepth` 仍然会跑完整流程（选层、最小二乘、
  剔外点、门控），从当时的统计反推是 **24 次/秒的无用拟合**（5 秒累计 120 次尝试），
  而且在 SLAM 线程上。留开关等于留一个持续烧 CPU 的死功能。
- **采用：保留兜底并补门控。** 修好数值后兜底能让那 32.5% 的「测不到」里一部分变成
  可用读数。但兜底原来只有「内点过半」，比修正链的门控松得多，直接放开会重演
  11-04 那次「路径 2 大量出现」的情况。
- **采用：禁止钉兜底读数。** 这是本次最关键的一条。11-04 删除版之所以给人
  「更不准」的印象，最可能就是兜底读数被钉成了折线端点——而段长是
  `|p_kf_i − p_kf_j|` 的刚体量，端点一旦来自估算，误差直接进读数。
  现在钉点强制要求 `method == 1`，**段长只可能来自真实地图点**。
- **否决：只修数值、不动结构。** 修好之后 `correctDepth` 会真的生效，而它的负面效果
  已经被两次实测确认（段长极差 8~23%）。只修数值等于直接启用一个已知有害的功能。
- **否决：把兜底也一起删掉。** 那样「测不到」会停在 32.5%，且 `fitPlaneAt` 这段
  代码从此没有任何调用者，不如连 `PlaneFit` 一起删干净——但兜底是十字无点时唯一的
  信息源，删掉等于放弃三分之一的可用时间。

## 验证

**未构建、未真机。** 本机 `wsl.exe` 被安全策略拦截，编译需用户执行。

预期变化与判读点：

1. `[M6] 面[兜底]` 的 `内点` 不再是 0 —— 方程解得出来了。若出现大量 `拟合失败`
   且 `候选` 也少，说明是局部点太稀，不是数值问题。
2. `路径2` 从 0 变成非零。参考 11-04 那次同源数值修复后的比例是 29%。
3. `[M6] * 测不到` 的占比下降（当前 32.5%）。
4. `[M6] 段长` **极差仍应接近 0%**。这是本次最重要的判据：如果段长开始跳，
   说明还有别的路径把估算值带进了 `p_kf`。
5. 按钉点时若提示无法钉，说明当前是兜底读数，属预期。

## 遗留

- **兜底精度未知。** 加了门控只代表「平面像样」，不代表「深度准」。没有真值对照，
  只能说它不会像无门控时那样乱给。
- **兜底不做选层。** 用的是 96 px 全窗口，墙角/多表面场景里「内点过半」会挑出
  占比最大的那一层，可能不是十字真正对着的那层。这是已知局限，选层方案在
  `exp/surface-depth` 分支上。
- **`fitPlaneAt` 的 double 修复未单独真机验证。** 它是这次能工作的前提，但只有
  「兜底能出数」这一条间接证据。
- **`[M6] 段长` 的心跳从每帧一次变成每帧一次**（仍在 worker 里，1 Hz 限流不变），
  但调用点从 `refinePinned` 挪到了 worker 直接调，锁的持有范围变小了。
