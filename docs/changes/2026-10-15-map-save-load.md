# 2026-10-15 存图 / 载图 —— teach-and-repeat 的地基

一句话：把地图存下来、载回来。这是路线导航那条线的第一步 —— 它交付的**不是能用**，
是「**图确实进来了**」：载进来的图这次还**用不上**，那要等重定位。

## 动机

路线导航定的是 **A 方案**（APP_DESIGN §10，2026-09-30）：2D 地图上同时画「你在哪」和
「路径点在哪」，人看着走，不做路径规划。里程碑 B 交付了**显示层**，但这条路断在
**图存不下来、载不回来** —— 「教」的那一趟和「重复」的那一趟接不上。

用户定的顺序：`① 存/载 → ② 重定位 → ③ 路径点 → ④ 导航显示`。这次只做 ①。

## 决策

### 一、保存并进「停止时那个弹窗」，做成**勾选框**

用户定的：「放到停止 SLAM 和保存轨迹一起询问」。

落点合适是因为 `curRunDir` 是**每次「启动」就建的**（`openHardware()`），和录不录制无关
—— 所以那个弹窗**每次「结束」都会弹**，不会出现「想存图却没弹窗」。

**用勾选框不用第三个按钮**：「留不留轨迹」和「存不存地图」是两个独立的轴，可以都要、
都不要、或只要一样。三个按钮里点第三个等于关掉弹窗，表达不了「都要」。

**挂 `setOnDismissListener` 而不是挂在按钮上**：那个弹窗有**三条**出路（保存 / 不保存 /
点外面取消），而「不保存」还会再弹**第二个**弹窗 —— 挂按钮就得挂四处，还会漏掉
「不保存但存图」。挂 dismiss 则不分按了哪个键都**只走一次**。

C++ 侧再加一道兜底：`saveState` 是 1（排队）或 2（保存中）时直接丢掉新请求。

### 二、一张地图 = **一个目录**

用户提的：「对同一张地图，轨迹存在地图根目录下，不同 session 共享」。

好处是解决了一个硬伤：`.osa` 直接摊在 `maps/` 下的话，「哪张图配哪条路径」只能靠
时间戳猜，而**地图和会话的时间戳本来就不同**。放进同一个目录之后，
**配对关系就是目录本身**。

**落法：`sessionDir` 就是地图目录。** 新建地图取新 stamp；**载入了旧图就用那张图所在的目录**
（`File(mapFile).parentFile`）。于是一趟趟的 `run-N/` 都攒在同一张图下面。

⚠️ 同一个目录下**可以有多份 `.osa`** —— §9 定的「另存、不覆盖」，所以入口页列的是
`maps/*/*.osa` 文件（每份是一份可载入的版本），不是列目录。

### 三、载图走 yaml，**不改构造函数**

`Settings` 读的键就是 `System.LoadAtlasFromFile`（`Settings.cc:475`），和上游那条旧路径同名；
而 `resolveSettingsPath()` 本来就每次都从 assets 重写那份 yaml 副本 —— 于是 Kotlin 在拷贝
之后追加一行就行，**上游一个字不用动**。

值**不带 `.osa`**，上游自己加后缀。没选图就不写这一行，走「从零建图」。

### 四、⚠️ 保存之前必须**把 LocalMapping 停下来**

`SaveAtlas` 序列化的是**整张 atlas**，LocalMapping 正在建点就会读到半张图
（上游只在 `Shutdown()` 之后存，就是因为它假设那些线程已经停了）。所以借它自己的
`RequestStop()` / `Stop()` 停一下，存完 `Release()`。

停不动时不死等（`Stop()` 在有重置排队时永远返回 false），200 ms 之后直接存；
`Release()` 是无条件叫的，所以那条路不会把 LM 卡死。

**代价**：`RequestStop()` 会 `mbAbortBA`（丢掉正在跑的那次局部 BA），`Release()` 会丢掉
排队的 KF。所以**只在会话真的结束之后存** —— 那时候没人要那次 BA 了。

### 五、⭐ 保存排给 **SLAM 线程**，主线程只发请求

- **不能在主线程**：序列化整张 atlas 要几秒，卡住主线程就是 ANR（弹窗回调就在主线程上）。
- **也不随手另起线程**：`stop()` 只停了**喂帧**，LocalMapping / LoopClosing 还活着。

排给 worker 是因为它是**那张图的唯一属主**。而且顺带拿到一条：存档期间万一又按了启动，
帧只会在队列里被丢，**不会两边同时动图**。

用户问过「为什么在帧间做，保存不是最后才存吗」—— 对，**它就是在最后**，
只是那个「最后」仍然不在主线程上。

### 六、⚠️ 载进来的图这次**用不上** —— 所以验收只到「图进来了」

构造函数载完 atlas 之后紧跟着 `mpAtlas->CreateNewMap()`，而 `mState==NOT_INITIALIZED`
那个分支（`Tracking.cc:1908`）**不受 `mbOnlyTracking` 管** —— 它照样初始化一张新图。
要用上旧图**只能靠重定位**（②）。

于是界面上完全看不出「图进来了」（当前图是新建的空图，小窗、轨迹、测距都看不到它）。
补丁 19 那个读数就是为此 —— 状态栏显示**「地图 N 张 / 关键帧 M / 点云 P」**，
M、P 不为 0 就是证据。

### 七、轨迹**仍然放在各自的 run 里**（用户否掉了我那版）

我原来按 §9 设计了「`path.csv` 跨 session 攒在一个文件里」，还定了行格式。
用户否掉：「各自轨迹还是放在各自的 run 里吧，到时候读的时候在处理」。

改对了，而且**更简单**：每趟的 `trajectory.txt` 是事实来源，**合并是读侧的一个视图**。
目录结构已经把「同一张图的 run 们」聚在一起了 ⟹ 「跨 session 共享」不需要新文件。

⚠️ 所以 **APP_DESIGN §9 要跟着改一句**（它写的是 `<名字>.osa` / `.markers.json` /
`.path.csv` 一组同名文件）—— 不改的话下次照它做就又绕回去了。

### 八、顺带把 `SlamBridge.kt` 的注释整份收敛了

用户指出一个我没意识到的机制：**我每次为了改一行去读文件，读到的全是长注释，
风格就被带跑了** —— 所以只把新加的那几行写短没用，得**碰到哪个文件就收敛哪个**。

同日追加：**代码注释里少用装饰符号**（⚠️ ⭐ ✓ ✗ ⟹ ← 那类），写成白字。
`docs/changes/` 里的不在此列。

### 九、⚠️ 自查抓到一个真 bug：存图状态**刷不出来**

`render()` 只由 ticker 驱动，而 ticker 的继续条件是「加载中 **或** 在跑」。而存图恰恰
发生在**刚停止之后** —— 那时候 ticker 已经停了 ⟹ 「正在保存地图…」会永远挂着，
不会变成「已保存」。

**修法**：加一个 `saving` 标志，`startMapSave()` 里置上并 `uiQueueTicker()`；
`render()` 看到状态 3/4 时清掉；ticker 的继续条件加 `|| saving`。

**这个坑在这个文件里是第二次**：上次是 `refreshMap()` —— 那时也以为「ticker 会喂」，
结果 idle 态没人喂。**「谁驱动刷新」这件事，每加一个异步状态都要重新想一遍。**

## 遗留

- **载过旧图之后再存，文件里是「两张图」，而且越滚越大。** 载入时 atlas 里放进了旧图，
  构造函数紧接着开了张新的，而 `SaveAtlas` 存的是整个 atlas。§9 早就预警过这一条。
  这次照存不误，弹窗里也写了这句；真正的解法（只存当前图）要动 `Atlas` 的序列化。
- **LoopClosing 停不住**：它没有配对的 stop/release（`RequestFinish` 是单向的）。
  正好闭环那一瞬间存档，理论上会读到半张图。
- **载进来的图这次用不上** —— 而且原因比原先写的更硬：**重定位够不着它**（见「更正三」）。
  不只是小窗上看不见（`getMapPoints` 只看当前图），是**根本没有任何东西会用它**。
  要做 ② 之前先单独设计这件事。
- **「重定位」按钮**（②）：§4.3 显式按钮、§4.4 三种失败提示、§4.5「成功也要让人看一眼」。
  ⚠️ §4.4 那三种要分开得知道**候选数**，而 `Relocalization()` 只回 `bool`。
- **APP_DESIGN §9 要改**（决策七）。
- **`run.json` 里写了什么没查过** —— 做 ④（读侧合并）之前先看一眼。
- **`SaveAtlasTo()` 会把 `mStrSaveAtlasToFile` 留下来**（改完不还）。现在没人调 `Shutdown()`，
  所以无害；但等于给将来埋了颗雷 —— 谁哪天调了 `Shutdown()`，就会在退出时**再存一次**。
- **保存没有进度条**：状态栏那行「正在保存地图…」是唯一反馈。
- **「多张旧图怎么选」**（§10 的老问题）—— 现在只按时间倒序列出来。
- **`MainActivity.kt` 的注释还没收敛**（决策八只做了 `SlamBridge.kt`，那个文件 1400 行）。

## 追加（2026-10-16）：两个决定被用户推翻了，加上「轨迹绑地图」的定案

### 📌 更正一：勾选框**作废**，改成**两个弹窗**

原设计是「轨迹的保存/不保存弹窗 + 里面一个存地图的勾选框」。用户否掉：

> 保存的时候这样设计，询问轨迹和保存地图分开，你现在这样强制保存了轨迹。

**「留不留轨迹」和「存不存地图」是两个独立的轴**，塞在一个弹窗里就分不开。改成
**两个串行的弹窗**：先问地图，问完（不管选了什么）接着问轨迹 —— 一次只弹一个。

⚠️ **顺序不是随便定的**：存地图要**当场把文件名定下来**，定完之后写出来的 `run.json`
才记得上它。「轨迹绑地图」是下一批的事，但这个顺序现在就得对，不然下一批要返工。

地图那个弹窗：目录里**已有** `.osa` ⟹ 「覆盖 / 另存为 / 不保存」；还没有 ⟹ 「保存 / 不保存」。
另存那一页带一个**「另存时连录像一起拷」的勾选**（用户要的）—— 不勾只拷
`trajectory.txt` / `run.json`，勾了连 `session-M/` 原始数据一起（可能几百 MB）。

### 📌 更正二：「一个目录下可以有多份 `.osa`」**作废**

用户定的新规则：

> 我们这个文件夹是按地图分的，所以一个地图文件夹只放一张地图。如果另存为就另开一个文件夹，
> 把 run 这些复制过去存地图；覆盖就直接覆盖这个文件夹的地图就好了。

⟹ **一个目录 = 一张地图**。覆盖 = 原地同名重写；另存 = 新目录 + 拷 run + 写新地图。

### ⭐ 「轨迹绑地图」的定案（下一批做）

这个问题是用户提出来的，而且**我先后想错两次**（都在下面留着）。最终模型：

**核心不变式：一个 `.osa` 文件 = 一个坐标系。** 轨迹有效的判据是「它记下的坐标系 == 当前的」。

内存里一个「**当前地图名**」（可为空）：

| 事件 | 当前地图名 |
|---|---|
| 新进程、选「新建地图」 | 空 |
| 选了旧图（构造时载入） | 空 —— 载入只是把图放进 atlas，位姿还没对上 |
| **重定位成功** | 那张旧图的名字 |
| **地图被重置** | 空（重新开始）；之后又重定位成功的话再置回去 |
| **保存地图** | 当场定名字：非空就覆盖原名，空就另起一个。**这个名字就是之后 run 要记的** |

落盘只有一个字段：`run.json` 的 **`map`** = 这一趟**结束那一刻**的当前地图名（没有就空）。
**没有 bool、没有 gen、没有回写。** 读轨迹时遍历该图目录下的 run，只取 `map` 对得上的。

**我在讨论中想错的两处**（记下来，免得下次又绕）：

- ✗ **「洞 1：全新地图的第一趟 run 会对不上」** —— 假象。它来自「先写 `run.json`、后问地图」
  这个顺序。**把顺序倒过来就消失了**：名字是同步定的，写 `run.json` 时它已经在手上了。
- ✗ **「洞 2：回写要区分代际，得加个 `gen`」** —— 假象。**根本没有回写**，也就没有「误改」。
  重置前那些记着空的 run **永远就是空**，那正是对的。
- ✗ **「重置基本回不去原图」** —— 我按 `Tracking::Reset()`（`clearAtlas()`）说的，可**真机走的是
  `ResetActiveMap()`**：它只清**当前图**、以及**当前图在词库里的条目**，**载入的那张旧图一动不动**
  ⟹ 重置之后**确实还能重定位回那张旧图**。

### 📌 更正三：**重定位只在「当前图」里找候选** —— 载入的旧图现在根本用不上

查 `KeyFrameDatabase::DetectRelocalizationCandidates(Frame*, Map*)` 的收尾：

```cpp
if (pKFi->GetMap() != pMap) continue;   // KeyFrameDatabase.cc:834
```

而 `Tracking::Relocalization()` 传进去的是 `mpAtlas->GetCurrentMap()`。载入 `X` 之后，
构造函数紧跟着 `CreateNewMap()` ⟹ **当前图是新建的 N** ⟹ 候选只在 N 里找 ⟹ **永远认不回 X**。
`Atlas::ChangeMap()` 更只有 `LoopClosing` 合并地图时才调，重定位**不会**把当前图切过去。

**所以上面「轨迹绑地图的定案」里有两条是错的：**

1. ✗ 「重置之后确实还能重定位回那张旧图」—— 我只查到「`X` 还在 atlas 里、词库里还有它」，
   **没查候选是怎么取的**。取的时候被「当前图」过滤掉了。
2. ✗ 「只存当前图就能顺带解决命名」—— 它假设重定位成功会把当前图切成 `X`。**不会**。

**更要紧的后果：这一版的「载图」实际上没有用。** 旧图进了 atlas，可它既不被跟踪用上
（重定位够不着），也不画出来（`getMapPoints` 只看当前图）。唯一可见的效果是状态栏那行
「地图 N 张」。启动弹窗里那句「这个 `.osa` 里会有 N 张图」现在按实际张数写，不再写死「两张」。

⟹ **② 的难点不在「加个按钮」**，在于「**载入的图怎么才能被用起来**」：要么让载入的图
直接成为当前图，要么让重定位能跨图找候选。两条都在 `Tracking` 的启动路径上 ——
**正是 §4.3 当初说「用手动按钮就不用碰它」而绕开的那一块**，现在绕不开了。

⟹ **做 ② 之前先单独把这件事设计清楚**，别混在实现里顺手做。
