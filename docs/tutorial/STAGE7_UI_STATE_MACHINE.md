## 1. 采集端状态机（已实现）

```
IDLE ──[开始准备]──► ARMED ⇄ RECORDING
  ▲                   │
  └───[取消准备]───────┘
```

| 状态 | A 按钮（左） | B 按钮（右） |
|---|---|---|
| IDLE | `开始准备` | `开始录制` 灰、不可点 |
| ARMED（未就绪） | `取消准备` | `强制开始` 红 |
| ARMED（就绪） | `取消准备` | `开始录制` 绿 |
| RECORDING | `取消录制` | `停止录制` |

**两条设计原则**，以后加状态时要守住：

1. **事实归模块，策略归编排层。** 相机只报告「我稳没稳」（`cam.ready`），
   IMU 只报告「我在不在出数」（`imu.ready`）；「要不要带着没就绪的状态硬上」
   是跨模块的判断，只能在编排层做。
2. **不为「等待」设超时。** 「等多久就不等了」由用户按那个红色按钮决定，
   不由定时器决定——超时自动放行 = 用户不知情的时候数据质量被降级了。

完整的设计取舍（为什么 IMU 挂在「准备」上而 SLAM 不挂、为什么强制开始不白等预热）
见 [changes/2026-09-21](../changes/2026-09-21-camera-preview-and-gating.md)。

### ⚠️ 一处修订（2026-09-26）

09-21 把**相机和 IMU 绑在「准备」上**（`开始准备` 打开相机 + 注册 IMU，
`取消准备` 关掉），理由是"两条线的开销都由那个按钮正当化"。

**但 SLAM 也需要相机和 IMU，而且它要常跑。** 所以绑定关系要重划：

| 资源 | 09-21 绑在 | 现在绑在 |
|---|---|---|
| **相机 + IMU** | 「准备」 | ❌ **已作废** —— 见下面那条 ⚠️ |
| **落盘** | 「录制」 | 「录制」（不变） |

于是这个状态机现在**只**管落盘，它上面的编排层（入口页 / 结束 / `onStop`）
负责相机和 IMU。见 [APP_DESIGN.md](APP_DESIGN.md) §7。

**两条设计原则不变**（上面那两条），只是"什么算就绪"的对象变了。

> ⚠️ **2026-09-27 再改：这个状态机连"落盘"那一半也搬走了，而且它现在管着相机。**
>
> **录制独立成了一个模式**（[CaptureActivity]，从入口页「录制模式」进），
> 和 SLAM 页**互斥** —— 理由是对焦所有权和性能，见 [APP_DESIGN.md](APP_DESIGN.md) §6.3。
>
> 所以上面那张表**整张作废**：相机和 IMU 既不归「准备」，也不归「SLAM 运行中」，
> 而是**归当前那个页面**。两个页面各自开各自的相机，因为它们永远不会同时开着。
>
> **§1 这套 `IDLE ─开始准备→ ARMED ⇄ RECORDING` 本身逻辑一行没改**，
> 连同它的两条设计原则一起，原样搬进了 `CaptureActivity`。

## 2. SLAM 侧状态机（未开始）

**目标：让用户永远知道「现在能不能测」，并且在不能测的时候知道该做什么。**

### 2.1 状态来源

`System::GetTrackingState()` 的返回值：

```cpp
enum eTrackingState {
    SYSTEM_NOT_READY = -1,   // 还没喂够数据
    NO_IMAGES_YET    =  0,   // 一帧都没进来
    NOT_INITIALIZED  =  1,   // 单目惯性初始化中 ← 尺度还没恢复
    OK               =  2,   // 正常跟踪
    RECENTLY_LOST    =  3,   // 刚丢失
    LOST             =  4,   // 完全丢失
    OK_KLT           =  5
};
```

### 2.2 交互规则

| 状态 | 测距入口 | 提示 |
|---|---|---|
| `NOT_INITIALIZED` | **禁用** | 「正在初始化，请缓慢移动手机」 |
| `OK` | 启用 | 「对准目标即可拍照」 |
| `RECENTLY_LOST` | 禁用 | 「跟踪不稳定，请放慢动作」 |
| `LOST` | 禁用 | 「已丢失定位，请对准刚才扫过的区域」 |
| 词袋还没加载完 | 禁用 | 「正在载入地图…」 |

**`NOT_INITIALIZED` 期间禁止测距是硬性要求**——此时没有米制尺度，
测出来的数字毫无意义。**这条不是体验问题，是正确性问题。**

### 2.3 引导用户

惯性初始化需要**运动激励**，静止举着手机永远初始化不了。
所以不能只显示一个转圈：

```
[ 正在初始化  ▓▓▓▓▓░░░░░  ]
     请缓慢左右移动手机，
     让相机看到更多角度的场景
```

初始化完成后给一个**明确反馈**（震动 / 颜色变化 / 音效），用户才知道"现在可以测了"。

> **进度条不要试图接 ORB-SLAM3 的内部状态。** 它没有暴露初始化进度，
> 硬凑出来的百分比只会说谎。按**时间**给一个粗糙的估计（比如「大约还要 10 秒」），
> 或者干脆用不确定的动画——**不确定比假确定好。**

### 2.4 测量结果的时效

回环优化会**改写历史位姿**，所以已经测出的距离在后续优化之后可能不再成立。

**信号是现成的**：`MapChanged()`（地图刚被回环 / 合并大改过）。

**处理方式已定**：测到 `true` 时提示「地图刚被优化，之前的测量可能需要重算」。
**测量结果不保存**，所以不需要考虑"存下来的结果怎么跟着地图更新"。
详见 [STAGE6_MEASUREMENT.md](STAGE6_MEASUREMENT.md) §7。
